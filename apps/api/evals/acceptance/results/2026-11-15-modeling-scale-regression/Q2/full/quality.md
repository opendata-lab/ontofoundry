# 青禾 Q2 质量核对

依据 README 的 11 条经营指标口径、六条最低业务规则及最终平台 batch。present 表示有对应定义，具体口径偏差另列。

| 材料指标 | 状态 | 核对 |
|---|---|---|
| 销售额 | present | 已完成订单为正事件、审核通过退款为负事件，分别按下单/审核日期 |
| 订单数 | present | 完成订单号去重，is_order_row = 1 |
| 客单价 | present | 销售额 / 订单数 |
| 毛利（含毛利率） | present | 定义存在，退款事件的毛利固定为 0，存在口径错误 |
| 会员销售占比 | present | 会员销售额 / 销售额 |
| 会员复购率 | explained | 未提交，最终答复说明统计期内先按会员聚合的表达困难 |
| 动销率 | present | 商品×日期数据集，分子要求 is_on_sale = 1 且 has_sales = 1，SKU 去重 |
| 库存周转天数 | present | 各日仓库及门店库存成本均值 / 日销售成本均值 |
| 盘亏损耗率 | present | 盘亏成本 / 同期销售成本，事件 UNION ALL 同源 |
| 准时送达率 | present | 准时已送达数 / 已送达数 |
| 优惠券核销率 | present | 已使用发放数 / 发放总数 |

present 10、explained 1、missing 0。未交付指标 1 个，基线未交付 2 个。共 22 个 metric 含支撑指标。最终答复一处称覆盖 11 个口径，后文明确承认少会员复购率，平台定义也确实缺此项。

| 六条业务规则 | 分类 | 最终表达 |
|---|---|---|
| 只有已完成订单计入销售 | filter | 销售事实 WHERE status = 已完成；状态枚举约束另计 |
| 退款审核通过才算完成 | derived，另有 filter | status = 已退款 AND approved_at IS NOT NULL，退款事件同样过滤 |
| 拒收不计库存 | explained | 答复称属性说明/数据集口径承载，未交付独立规则 |
| 生鲜只能存冷链仓 | rule，表达有偏差 | 约束商品 storage_type 为冷藏/冷冻，未约束实际仓库 wh_type |
| 临期定义 | derived，部分表达 | produced_on + shelf_life_days * 2/3 为临期起始日，没有剩余保质期比较或折扣规则 |
| 闭店门店不计在营 | explained | 说明中保留，表达式仅 status IN (营业, 装修, 闭店)，不能单独定义在营范围 |

主要表达分类为 rule 1、filter 1、derived 2、explained 2。rule 1 有语义偏差，derived 的临期项仅交付起始日。6 条 rule 中无 value_type 约束，另有 2 条对象属性枚举约束和 4 条业务规则。枚举约束没有补齐闭店排除条件。

## 实体与关系

33 个 object_type 覆盖 README 按主单/明细展开的 30 个业务类型，另有企业、促销参与商品、日历日期。企业另建 1 个文档实例。技术日志与迁移备份均排除，dim_date 用作日历维度。

库存快照到仓库、门店两条关系都存在，均直连 location_id。location_type 的使用条件写在关系说明中，data_join 本身只含编号列，调用方需要遵守类型条件。

## 口径发现

- 毛利聚合 sales_fact.gross_profit。销售分支为实付减成本，退款分支的 sales_amount 为负退款金额，但 gross_profit 固定为 0。因此实付 100、成本 60、退款 20 时，材料定义应为净销售额 80 − 成本 60 = 毛利 20，当前定义得到 40，毛利率也受影响。该反例由最终 SQL 与 metric 定义推导，未执行问数。
- 生鲜冷链规则只查商品存储要求。商品要求冷藏、实际被放入常温仓时，该表达式仍可通过。材料要求的是实际存放仓库类型。
- 盘亏数量直接为 book_qty − counted_qty，盘盈时会得到负值，材料定义要求只有实盘少于账面的部分算盘亏。损耗指标数据集另有 counted_qty < book_qty 条件，其损耗统计没有该负数问题。
- 日历维表限定了动销指标可取的日期。库存平均值只覆盖存在库存快照或销售事件的日期，空日期没有行。此处记录生成定义的适用范围。
