# 业务原则与交付

信任与提案边界见系统底线；执行轮数与修正见 SKILL。

- 复用已有 UUID，只提变化；同名不证明同义，同号不合并事实。定义匹配先看归属、标识、范围及同义词。
- 一个指标只引用单 Dataset；ratio 两个分量必须是同 Dataset 的数值 simple。跨表口径（例如退款率）先提议基于表达式的 Dataset 再在其上建指标（写法 `show_example.py dataset --variant query`）；确实无法表达的单项不出提案，合法范围继续，在最终说明列缺项、原因和建议，不静默改公式，不新增状态。
- 保持算法、NULL、去重、过滤、时间和快照口径。声明的唯一性、基数与覆盖必须有业务依据，不能由单行样本证明；数字坑例见各抽取方法。
- 物理来源只用已关联或材料明确的已登记表，不臆造表列；尚未同步的表可提议 Dataset；无物理列时只提语义和空列的表数据集，不生成依赖未知列的映射、SQL 或指标，说明缺项并提示“先在数据管理同步该表，再发起补齐”，不在运行中操作同步。
- 模型只存业务语义；SQL 方言、类型转换、精度、日期补齐、空周期显示和性能选择由查询 Agent 处理。可推导关联、统计、标题显示不存模型。
- 不新增或改动人工证据；更新保留原人工证据内容及 UUID。材料原 ID/hash、原行号、引文须真实。引文存在不代表必然支持结论。
- 只有缺少会改变业务含义的决定才问用户，给具体数字例子、选择后的不同结果与推荐。格式问题查正例修复，耗尽走失败路径，不转为业务提问。

## 交付约定

用简体中文 Markdown 简述修改和依据；display_name 叫“名称”，name 叫“英文标识”。说明未交付项及建议；未同步表明确提示“先在数据管理同步该表，再发起补齐”。已有提案才提示用户在右侧「提案」中审阅。不展示内部路径或契约实现字段。

程序保证格式、引用和接收边界，不能证明算法等价、材料蕴含、业务唯一性或实际数据覆盖；这些仍须证据和用户审阅。
