# 指标与规则抽取

章节原行号索引：决策 5–12行；时间与完整算法 13–20行；规则分工 21–25行。用 read_input --start/--end 定点读取。

## 决策

为指标记录“行粒度、单Dataset、度量、算法、固定过滤、业务时间、快照、NULL／去重”。直接聚合用simple，同Dataset的两个数值simple构成ratio，复杂OR／CASE／排空算法保留expression；分子分母在不同表时先建基于表达式的Dataset（UNION ALL 各带日期），再建两个simple和ratio。解析器接收不等于业务等价。

坑：两行提交数3和5，SUM=8而行数COUNT=2；可空列值为7和NULL，COUNT(列)=1而行数=2。1单完成、1单取消，完成率1/2；分母也过滤完成会成1。逐行比率1/2与9/10的平均0.7不等于总体10/12。各分量过滤和时间独立，零分母NULL不改成0。

跨Dataset销售100、退款10/20：先提议基于表达式的Dataset，用 UNION ALL 让销售和退款各成一行、各带业务日期，再建销售额、退款金额两个simple和退款率ratio，结果30%；若把退款明细JOIN到订单后求和，销售变200、退款率变15%。查写法用 show_example metric。

## 时间与完整算法

坑：1月30下单、2月2付款100，2月按下单为0、按付款为100。需问时间口径时推荐已有已确认定义，无决定则由用户选。模型保存业务时间和快照声明，方言与日期不齐交查询Agent。

坑：末日北区10，南区只前日7，全表末日汇总10，不能逐区回退成17。先取全表周期末日，再加过滤；两个Dataset末日分别2日／3日，不强制相同。两重叠7天窗口各10且共有4，总体16而不是20；总计重聚合，均值／去重／比率不相加。季度2月无值不自动设0。

完整expression保留NULL、去重、OR和CASE，不能为了simple模板换口径。列路径按示例使用Dataset name，Rule用对象属性路径；自然语言与任意SQL不冒充可执行表达式。

## 规则分工

坑：“年龄≥18”是约束，17岁和20岁两记录仍2条，规则不执行删除成1条；“数量×单价”计算2×30=60归字段绑定，不用Rule假装返回60；父3人中主管2人归derived_by，不用Rule筛成2人。derivation Rule只保存业务派生说明；不存在独立解释需要时不重复存同公式。

需问：“订单必须付款”约束是否允许1笔未付款暂存？给“保留并说明1条违反”和“成员只看已付款而少1条”的区别，推荐约束归Rule，只有明确成员范围才改成员定义。规则须归具体对象／属性／关系。
