# 文档实例抽取

章节原行号索引：决策 5–12行；身份与更新 13–18行；证据定位 19–23行。用 read_input --start/--end 定点读取。

## 决策

先区分定义与具体陈述：“员工需有主管”是规则，“小岚向小舟汇报”是2文档实例和1关系实例。确定具体类型、明确值和两端；示例／假设／否定／计划不等于成立事件。

坑：材料说“示例采购2件”，不能当已发生采购2件；“计划买3件”不证明已有3件。原文金额未知，邻行50不能复制成50；0元与false是2个真实值，不是缺失。只缺非必要属性不阻断其他实例，缺编号不补“员工001”。

需问：示意2件是否纳入实例范围？推荐只存用户明确要求的实例；纳入后统计多2件，纯示例则不增加。写法用 show_example material_object／material_link。

## 身份与更新

坑：编号01的两个UUID仍2实例，按编号合并会丢1实例；链接端点应引用具体实例而非类型。values 用有效属性name，标题按定义推导，不单存展示文字。只有用户明确指向UUID才更新，保留已有人工证据及UUID，不由聊天回答生成作者／确认时间。

需问：同号金额50与80无修订说明，选择保留2实例，还是更新指定UUID为80并追加证据？推荐无明确修订依据先保留独立；影响已有实例时等待用户决定。

## 证据定位

从工作包取原材料ID/hash，用read_input按原行号读足以支持结论的范围并核对quote。坑：原40–50行的第5行是44，引用5会指错39行；2份材料不能混用hash。不得改原文迁就结论。真实引文“金额待确认”即使确在1行，也不支持写50；引文存在不证明业务蕴含。原材料未读的10行不是没有其他实例，依范围继续回读。证据真实性由服务端终验。

需问：同一记录两处时间不同，10日与12日是否修订？给保留2证据／确认新版12日的结果，推荐保留来源并请求影响业务值的决定，不自行用后出现的覆盖。
