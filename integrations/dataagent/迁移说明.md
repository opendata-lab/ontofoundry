# 三技能迁移说明

日期：2026-10-21。适用于 0.1.0 版三技能。最低平台版本为当前 0.1.0，必须同时具备 manifest 的 2026-10-21 core-1 能力基线；版本号本身不能区分同版本开发快照。此包不升级平台、不迁移或清空数据库。

## 2026-10-27 更新

- DataAgent 版本要求同 10-26，两个 Agent 的系统提示词本次未变，无需重新发布。
- 平台：执行数据库迁移到 20261026_000001（建模串行化与原子化）。迁移删除旧的“不可接受”提案和失败批次，把“被取代”的提案以及新一轮开始后旧批次里仍待审的提案改为已拒绝。
- 技能：合并脚本缺少平台检查配置时报错，不写结果；删除 `--drop-unacceptable` 和 `check_result.py --publish`。两轮修正仍不通过就整批不交，在回答里说明原因。重新安装三个技能并重启 DataAgent，用新会话验收。
- 使用变化：同一会话一次只做一件事。运行中、结果处理中，或还有待审提案时，不能发起新一轮建模，也不能直接编辑草稿；先处理完待审提案，或在提案上修订。

## 2026-10-26 更新

- 需要 DataAgent main 6f2bf6e8 或更新（问题卡片、计划卡片与计划模式；计划获批准前，检查片段和生成结果的脚本会拒绝执行），升级后执行 DataAgent 数据库迁移到 20261026_000029。平台需执行迁移到 20261025_000001（会话模式），漏执行时新建会话会报 500。
- 建模 Agent：按 `agents/agent_ontofoundry.md` 更新系统提示词并发布；高级设置“计划等待超时后”保持“继续等待用户确认”，计划不自动批准。
- 技能：概念范围改为在同一运行中提交计划、批准后继续抽取；待确认文件与 `--prior-plan` 已删除。重新安装三个技能并重启 DataAgent，用新会话验收。覆盖安装不会删除旧文件，安装后删除各技能 `references/examples/protocol/` 下残留的 `needs-input*.json`。
- **平台检查必须可达**：合并脚本只在平台检查通过后才写结果，连不上就不交结果。DataAgent 所在机器要能访问 OntoFoundry 的 `public_base_url`（工作包里 MCP 地址的主机），部署后在 DataAgent 容器里用 `curl` 访问该地址确认。
- 平台：入库时不再自动发起“建模修复”运行，对话里的平台消息和“重试”按钮已删除；失败原因显示在这次回答的错误块中。
- 平台：没有结果文件的运行直接失败，不再进入“等待回复”。停在等待回复的旧会话，下一条消息按新流程重新开始。

## 2026-10-23 更新

- 需要 DataAgent main 9f1e6af6 或更新：Skill 工具加载技能时返回“本技能目录”，技能入口按它找 `scripts/`，旧版 DataAgent 下会找不到脚本。同版还包含：按真实用量判断上下文压缩、使用模型配置的上下文窗口、工具报错统一格式、MCP 报错脱敏，以及系统提示词保存（启动时执行 DataAgent 数据库迁移 20261022_000028）。
- 在 DataAgent 后台“模型”里为所用模型填写上下文窗口（按模型实际支持的值）；未填写时按部署默认 64K 计算，长抽取会频繁压缩、缓存失效。
- 平台：同一轮既交提案又写待确认文件时提案照常入库，问题写在 Agent 回答里；两个 Agent 的系统提示词本次未变，无需重新发布。
- 安装：按下文重新安装三个技能并重启 DataAgent，新会话验收。

## 迁移前

- 确认平台工作包、完整提案 v1、execution 修正预算、本体检索四工具与 resolve_entity 已部署。两个抽取技能的 Schema 从同版平台契约生成，不能跨版混装。
- 备份当前技能目录、两个已有 Agent 的正文、挂载和 MCP 配置。停止旧建模运行与续跑，保留失败诊断和修正计数，旧会话不混用新技能。
- 迁移包内是三个独立技能 ZIP（ontology-discovery、entity-extraction、semantic-grounding），每个 ZIP 顶层只有自己的技能目录。仓库开发时用 `make -C integrations/dataagent zip` 生成。

## 安装与后台配置

1. 在 DataAgent 后台分别上传三个技能 ZIP；或把它们解压到技能根目录（`SKILLS_ROOT_DIR`）。重复安装会覆盖同名文件，完整替换请先备份并移走旧的同名技能目录，避免残留文件。
2. 在后台登记 OntoFoundry MCP。地址模板 `/api/v1/ontology/workspaces/<workspace_id>/mcp`，凭据取平台授权配置；确认 search_ontology、get_ontology、search_objects、get_object。建模使用每次工作包的运行级 MCP 授权，不能把运行 token 固化到包。问数的 mysql.query／doris.query 属于 DataAgent 自有能力，独立按授权配置；按现网要求设置 ODW_BACKEND_BASE_URL、ODW_AGENT_SERVICE_TOKEN，不把令牌写入文档。
3. 已有 `agent_ontofoundry` 挂载 ontology-discovery 与 entity-extraction，max_turns=40，由 Agent 按任务和材料动态组合。已有 `agent_ontofoundry_qa` 挂载 semantic-grounding。将 agents/*.md 中“系统提示词：”后的正文同步到后台并发布，配置段不粘进正文。问数的读取顺序与查询语义规则已迁入技能，不能只更新瘦身后的提示词而漏装技能。
4. 停用旧 ontofoundry-modeling 挂载，备份后移走旧目录，由运维重启 DataAgent，确认 capabilities 只识别三个新技能。安装脚本故意不自动删除旧目录。
5. 源码 shared 不能单独安装，skills 下专属源码也不能直接复制运行，必须使用组装好的技能 ZIP。

## 验收与回退

先执行离线 pytest、offline_budget 和 make zip，再安排新会话真实验收。DeepSeek 运行前另行确认预算。至少覆盖文档＋表结构发现、文档实例、两技能组合成一个结果、增量／补齐、修正续跑、问数缺定义及多候选追问；核对 ≤T4 首片段、完整合法范围、中文证据和缺项、Schema fetch/search=0、实际轮数与 U/C/O、压缩缓存及授权边界。离线字节预算不是模型 token 实测。

当前实体消歧服务尚未上线，技能不调用；问数结构化理解由 Agent 输出，自动写入问数运行记录、专门实例抽取入口与新版平台实例契约需随路线图后续工作联验。本包不声明这些平台功能已经实现。

回退时备份本次诊断，成套恢复旧技能和两个 Agent 正文、挂载，再由运维重启；不要用恢复后的旧会话重置修正预算。本次没有数据迁移，不执行历史 core-1 发布中的清库步骤。
