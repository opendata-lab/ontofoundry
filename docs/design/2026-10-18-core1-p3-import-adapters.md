# core-1 P3 机械导入适配器实施设计

基线：main `32b56ee`。语义与转换规则沿用 `2026-10-14-core-model-and-format-adapters.md` §4、§5、§7；不新增模型字段或数据库结构。

## 已确认决定

| 决定 | 内容 |
|---|---|
| 优先级 | 用户确认先推进 P3→P4→P5；P2-18 多分支、多跳路径的结构化编辑降为后续便利性优化，现有表达式编辑继续可用 |
| 本期边界 | 只提供纯 Python 转换库与报告；不开放 API、导入界面、提案确认或发布；不部署、不执行迁移 |
| 输入 | 原生 core-1 四字段单文件；Ossie 0.2.0.dev0 ontology 文档及内嵌 ontology_mappings；ZIP、独立 OSI/mapping documents 拒绝 |
| 输出 | 每次返回通过核心校验的独立子图；不支持或不能闭合的条目及依赖留报告，不能塞进非法半成品 |
| 报告 | 复用主设计的字段、outcome、completion_status 和 RT 编号；源码定位指向实际 JSON pointer，解析失败只用真实行列；保存完整原片段 |
| 身份与哈希 | 采用主设计 UUID5 作用域；内容哈希包含原始输入身份、确定性转换结果及报告，不依赖文件名或随机 id |
| 证据 | 原生人工证据保留；材料证据由独立解析函数按目标 SHA 解析，P3 不访问数据库。未找到材料时仅丢该证据并报告，保留事实 |
| 测试 | 全部编辑完成后统一执行新适配器测试、架构约束及完整后端检查；保持 A/B 原始样例，不把输入裁成易转换子集 |

## 实现分工

`adapters/base.py` 提供接口、结果和报告；`adapters/documents.py` 处理 JSON 和定位；`native/importer.py` 保留核心身份并处理证据；`ossie/translation.py` 汇总报告和合法子图；`ids.py`、`extension.py`、`importer.py`、`mappings.py`、`metrics.py` 分别负责身份、扩展、本体、物理映射和指标。现有固定官方校验器及 vendor 资源原样保留。

任何规则、派生条件、字段表达式和指标都复用核心解析与校验。适配器只改写已解析标识符，不替换 SQL 字面量；不执行输入 SQL，不连接业务数据源。
