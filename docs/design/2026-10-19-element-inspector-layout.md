# 本体详情弹窗：全量布局与交互方案

状态：已确认并完成代码实施（2026-10-19）；按用户安排暂未运行测试、构建或截图验收。

## 1. 范围与方向

一次审阅对象、关系、数据集、指标详情的查看与编辑布局，不再逐项确认小问题。只调整界面组织与交互，不改变模型、权限、接口、保存预检和数据查询行为。

遵循 [企业 ToB 产品界面设计共识](2026-10-19-tob-ui-design-principles.md) 和 [当前视觉规范](2026-10-17-ui-visual-consistency.md)。已实现的固定弹窗框架和概览 40% / 60% 比例作为基础；原版截图用于参考信息分组与空间组织。

对象包含概览、属性与映射、关系、规则、实例；关系类型包含概览、数据绑定、规则、实例。数据集和指标沿用共用外框，不为保持形式一致强加新页签。

## 2. 共用框架

```text
┌───────────────────────────────────────────────────────────────┐
│ 销售订单 sales_order           [编辑] [复制链接] [展开] [关闭] │
│ 对象类型 / 映射状态                                           │
├───────────────────────────────────────────────────────────────┤
│ 概览  属性与映射 8  关系 3  规则 0  实例                       │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│                当前 tab 正文，独立滚动                        │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

顶部操作区的两种状态：

```text
查看： [编辑]         [复制链接] [展开] [关闭]
编辑： [取消] [保存]  [复制链接] [展开] [关闭]
```

- 查看与编辑保持同一外框、标题和页签位置；编辑时在原“编辑”按钮的位置显示“取消”“保存”，不设置底部操作栏。
- 页签顺序稳定，规则为 0 时也保留页签；实例及数据绑定继续遵守现有权限与新建状态限制。
- 查看时突出内容；编辑时显露输入和操作。切换 tab 保留同一份草稿，由顶部统一保存，不增加分区保存。
- 普通弹窗沿用 1100px 宽、800px 高及视口边距约束；展开使用更多可用空间。字号仍为 12/13/16px，间距沿用既有档位。
- 同级内容用标题和分割线组织，不层层套卡片；页签内避免正文与表格同时形成纵向滚动条。

## 3. 对象 · 概览

```text
基础信息（约 40%）                 关系（约 60%）    [全部关系]
──────────────────────────────     ────────────────────────────
名称       销售订单                ┌──────────────────────────┐
技术名     sales_order             │          客户            │
描述       一张订单代表……          │           │              │
父对象     业务单据                │        销售订单          │
子对象     线上订单、门店订单      │           │              │
标题属性   订单名称                │          商品            │
同义词     交易单                  │                          │
标签       销售                    │                    + − □ │
──────────────────────────────     └──────────────────────────┘
数据来源
绑定方式   独立绑定
主数据集   销售订单每日快照
映射状态   已映射
成员条件   按现有定义展示
```

- 左侧只设“基本信息”“数据来源”两区，不设“实例标识”区；标识约束在属性表中查看和维护，不从模型删除。
- 名称、技术名、描述均有标签；左侧单列键值对齐，长值自然换行。成员条件仅在适用时显示，来源证据在对应内容后按现有证据展示。
- 右侧图形占满分配区域，节点名称可读；保留缩放、适应画布和点击对象行为，不增加装饰。
- 编辑：基本信息按“名称/技术名”“父对象/标题属性”“同义词/标签”成对排布，描述整行；成员条件按现有能力展示。数据绑定仍到“属性与映射”处理，避免两处编辑同一配置。

## 4. 对象 · 属性与映射

```text
数据来源：绑定方式 · 主数据集                     [管理数据来源]
───────────────────────────────────────────────────────────────
属性列表（约 55%）                  选中属性（约 45%）
[搜索名称或技术名] [添加属性]        订单金额 amount       [删除]
属性           类型    约束          ────────────────────────────
订单编号       文本    标识·唯一     基本信息
订单金额       数值    必填          名称、技术名、类型、说明
创建时间       日期    —             ────────────────────────────
                                    约束：标识 / 唯一 / 必填
                                    ────────────────────────────
                                    数据绑定
                                    列 / 计算
                                    来源 [选择]
                                    字段 [选择或输入] / 多行表达式
```

- 采用 Foundry 式列表与配置区分离，不再把完整编辑表单塞进表格单元格或插入整行。
- 来源区默认保留绑定方式和主数据集摘要，按需展开完整来源；尚未绑定时进入编辑自动显示来源配置。
- 查看时约束列显示标识、唯一、必填文字，不使用整列禁用复选框；配置区展示完整定义。编辑时在同一区域出现控件。
- 列表可搜索，选中行明确高亮；新建属性自动选中，直接打开某个属性时选中对应条目。
- 继承属性显示来源与只读说明，保留独立绑定场景下的既有绑定修改能力。标识锁定、技术名冲突与来源约束沿用现有规则。
- 来源选择、列选择和计算表达式使用配置区完整宽度；计算表达式使用多行输入。
- 窄容器时配置区位于列表下方；仍由顶部统一保存，不增加属性级保存或新的数据预览能力。

## 5. 对象 · 关系

2026-10-19 用户确认按参考 Foundry 的列表与详情分区实施。

```text
搜索关系                                      [新建关系]
──────────────────────┬─────────────────────────────────
关系列表              │ 来源对象 ──关系名称──→ 目标对象
名称 / 对端对象       │ 基本信息：名称、描述、方向、基数
基数 / 定义来源       │ 反向名称、定义来源
选中行高亮            │ 数据绑定：完整绑定说明或配置
                      │ [打开关系定义]
```

- 列表用于选择和比较业务连接，不把完整绑定条件塞入单元格；搜索匹配名称、技术名和对端对象。
- 右侧先展示两端与关系语义，再展示数据绑定。关系定义仍通过原有关系详情维护；仅既有允许的继承关系本对象绑定可在右侧直接编辑，纳入顶部统一保存，不增加分区保存。
- 保留现有权限及只读说明；自关联的正反向行使用不同选择标识。

## 6. 对象 / 关系 · 规则

2026-10-19 用户确认采用列表与详情分区；内容沿用本产品规则，不照搬 Foundry Action Rules 的执行语义。

```text
搜索规则                [类型：全部]            [添加规则]
──────────────────────┬─────────────────────────────────
规则列表              │ 规则名称
名称 / 类型           │ 基本信息：技术名、类型、所属
所属 / 继承来源       │ 规则内容（完整、多行）
选中行高亮            │ 说明 / 来源证据
```

- 列表不再以截断表达式为主；选中规则后在右侧完整阅读，编辑在同一位置显示表单，所有变更由顶部保存。
- 名称搜索与类型筛选共同作用，新增规则清除筛选并选中新规则；继承规则保持只读。
- 既有表达式、所属和证据字段不变，不增加运行状态、规则执行或关联模型。

## 7. 对象 / 关系 · 实例

2026-10-19 用户修订并确认：使用来源过滤器单选文档或数据库，先不合并展示；不使用来源页签或分段切换器，不提供“全部来源”。选中后右侧预览，收起后表格恢复全宽。

```text
[搜索实例] [来源：文档/数据库 ▾] [数据日期]       [列设置]
──────────────────────────────┬─────────────────────────
实例名称  业务属性…           │ 实例名称          [收起]
当前所选来源的实例            │ 基本属性（单列）
选中行高亮                    │ 关联实例（按关系分组）
                              │ 来源信息与文档证据
[上一页] 第 n 页 [下一页]     │
```

- 有文档事实时默认文档；无文档事实且数据库可用时默认数据库。数据库不可用时回到文档，数据库选项禁用。
- 每次只读取和分页一个来源，每页 8 条；文档在本地分页，数据库沿用服务端游标或草稿 offset。切换来源、搜索和日期重置分页及选择，不引入混合结果、合并身份或全局总数查询。
- 来源在过滤器及详情展示，单来源表格不再添加重复的来源列。日期明确只筛选数据库记录。
- 默认展示最多四个非标识业务属性，跳过已作为实例标题展示的属性，避免名称重复；通过列设置可选择其他已有属性。
- 选中详情按基本属性、关联实例、来源信息组织；窄容器改为下方，收起后表格恢复全宽。关系类型实例页仍只支持现有文档关系事实，不伪装支持数据库关系查询。
- 加载、错误、空结果分别提示；只读、权限和证据语义保持既有行为。

参考依据：[Foundry 结果表格与右侧预览](https://www.palantir.com/docs/foundry/object-explorer/view-results)、[Foundry 筛选结果](https://www.palantir.com/docs/foundry/object-explorer/filter-results)。来源单选及默认规则为本产品的设计取舍。

## 8. 单条关系详情：按任务组织，不嵌入关系列表

2026-10-19 用户确认简化关系详情，并明确当前已选中单条关系，不能再加入关系列表；后续补充“需要 Tab 也可以”，因此无页签不再是硬约束。关系目录、对象内关系列表与单条关系详情各自保留自己的上下文。

```text
签约方 signer                         [编辑] [复制链接] [关闭]
关系定义    实例 1
───────────────────────────────────────────────────────────────
合同（多） ──签约方──→ 当事人（一）
───────────────────────────────────────────────────────────────
数据绑定 · 属性对应
合同                     对应                     当事人
签约当事人编号            →                      当事人编号
───────────────────────────────────────────────────────────────
补充信息：只展示有值字段，全部为空时显示暂无补充信息
规则 0 · 暂无规则
```

- 用户允许按需要使用 Tab，当前已确认并实施按“关系定义 / 实例”两个任务组织，定义内依次聚合两端、绑定、补充信息和规则。单条详情始终不嵌入关系列表或大型端点画布。
- 关系定义直接展示两端、数据绑定和补充信息；规则在定义内按需展开，实例独立为 Tab。原能力和权限不变，实例仅既有文档事实。
- 关系方向与基数在同一紧凑端点行表达，删除标题下重复端点。按既有 multiplicity 推导两端的一/多，不新增字段。
- 查看状态只展示有值的补充字段；反向名称、描述、同义词、标签全部为空时显示“暂无补充信息”，编辑仍保留完整字段。
- 属性对应明确显示来源对象及属性、对应方向、目标对象及属性；映射表对应明确显示表、列及对应对象键，不仅展示两个未注明归属的字段名。
- 无规则且非编辑状态时显示“规则 0 · 暂无规则”，不提供空展开；编辑状态保留规则展开与添加入口。
- 编辑仍在顶部原编辑按钮位置显示取消/保存；关系定义、绑定和规则归同一草稿及保存预检，不增设分区保存。
- 旧规则深链接定位定义页并展开规则；旧绑定深链接归到定义页；实例深链接仍进入实例页签。新建时不显示实例。
- 只简化单条关系详情，本体关系目录不在本轮改为全局列表加编辑器。

- 数据集基本信息紧凑排列，物理位置和长说明整行；字段表用足弹窗宽度，不受表单最大宽度一起限制。
- 指标编辑把共有字段和类型专属字段分区，表达式使用整行；预览区与定义分开，保留现有权限及计算行为。
- 不新增后台能力，也不把 SQL 执行细节写入语义模型。

## 10. 状态与交付边界

- 计数为零显示 `0`；无值、加载和错误分别表达。业务空状态说明缺少什么，有权限且已有操作时再提供入口。
- 保留真实业务字段及其修改能力；“不设实例标识分区”不等于删除标识定义或约束。
- 保存中沿用现有禁用、影响预检与确认；不再为普通布局操作添加确认步骤。
- 不新增键盘操作需求，不更换组件库、配色体系或字号档位，不重做品牌。
- 本次未运行测试、构建或截图验收。代码已按 [实施计划](../plans/2026-10-19-element-inspector-layout-plan.md) 连续实施，当前交由用户查看实际效果；集中验证后再更新截图基准。

## 11. Fabric IQ 与 Foundry 页面对比

对比日期：2026-10-19。以下保留公开资料观察；其中列表与配置区分离的修订已由用户确认采用。对标范围为 Fabric IQ 的 Ontology 配置体验及 Foundry 的 Ontology Manager，不将 Foundry 面向业务实例的 Object Views 当作类型定义编辑器。

依据为官方文档与可公开访问的截图，没有登录两家产品实测；截图属于文档所展示的版本，不据此推断各租户最新界面。Fabric 本次以当前文档明确描述的结构为据，不推断像素尺寸、字号或控件位置。

### 可核实的页面组织

| 维度 | Fabric IQ | Palantir Foundry | 我们的方案与建议 |
|---|---|---|---|
| 工作空间 | 画布与 Explorer 定位实体，再进入实体详情；详情分 Configure / Instances [F1] | 对象类型使用左侧页导航和右侧工作区；概览、属性编辑、关系各有视图 [P1] | 保留已确认的弹窗及展开态；复杂配置时给正文足够工作空间 |
| 概览 | 配置页聚合属性、绑定、关系、指标及元数据 [F1] | 概览分元数据、属性、关系图、数据等区域 [P1] | 按任务分区比增加卡片装饰更有价值；保留基本信息与数据来源两区及关系图 |
| 属性编辑 | 管理属性绑定可展开，复杂绑定进入专门配置页 [F2] | 官方属性编辑器截图将列表、右侧配置和底部数据预览分区 [P2] | 我们原提议的整行展开可缓解拥挤，但右侧独立配置区更便于反复选择、比较属性 |
| 映射 | 先选来源，再配置属性与来源列；管理绑定与查看实体分层 [F2] | 截图提供 Properties / Column mapping 两种视角 [P2] | 来源摘要、属性定义与选中属性的绑定应层次清晰，避免一行塞满全部控件 |
| 保存 | 绑定配置具有自己的 Create / Save 等操作 [F2] | 应用右上角统一 Save，再审阅改动、处理错误与警告 [P3] | 保留顶部原位取消/保存和现有预检，不照搬两家提交语义 |
| 实例浏览 | Instances 与 Configure 分开 [F1] | Object Explorer 面向实例搜索分析，与 Ontology Manager 职责不同 [P4] | 保留独立实例 tab，不把实例详情混进类型定义表单 |

### 已采用的主要修订

以下属于基于页面结构的设计判断，不表示两家产品采用完全相同的交互。

第 4 节已由复杂属性“整行展开编辑”改为“左侧列表＋右侧选中属性配置”。现有顶部统一取消/保存、属性与映射 tab 名称及其业务能力保持一致。

- 查看状态展示选中属性的完整定义，编辑状态在同一区域显示控件；不把完整表单插入列表中造成行位置大幅变化。

- 不为模仿 Foundry 新增数据预览、Actions、运行状态或使用统计；本产品已有的预览能力在自己的位置保留。
- 原概览 40% / 60% 是本产品已确认的布局，不宣称来自两家产品的统一比例；颜色、字号、密度继续由本项目规范决定。

### 17.1 正反向语义组织（参考用户提供的 Foundry 截图）

### 数据集物理位置选择（2026-10-19，已确认）

数据集编辑中的库 / Schema、表或视图使用可搜索的 Ant Design Select，从现有数据目录接口读取；不是自由文本。始终展示“数据库连接”下拉，再选库和表；能唯一匹配已有数据库类型时预选连接，否则要求选择。数据库类型由连接带入，不在编辑表单单独选择。选择表后读取并带入字段名称、类型和注释。连接选择只属于当前目录浏览状态，不新增核心模型字段；物理来源仍由既有服务端规则解析，多连接歧义仍由服务端处理。

变更连接或库时清空后续表、字段与快照日期选择，避免沿用上一张表的元数据。选择新表重置快照日期，同表重新读取保留原选择。加载中禁用相关控件；失败显示具体错误及重试，保留已有配置不自动覆盖。导入的旧值即使暂不在目录中也能显示，不伪造可选表。沿用已有 FormRow 布局和间距，无新增视觉变量。

### 数据库连接与快照表配置（2026-10-19，当前生效）

名称与数据库连接同行，库 / Schema 与表或视图同行；数据库类型在建连接时确定，数据集编辑不再单独选择。选择连接和表后将连接方言带入已有 dialect，连接 id 不新增到核心语义模型。查看状态可保留数据库类型只读信息。

快照配置改为先勾选“快照表”，勾选后才显示必填的“快照日期字段”下拉，未勾选不显示日期选择。数据集详情和从目录登记复用同一控件。勾选但未选择日期是未完成的表单状态，不能保存/登记；关闭时清空 snapshot_date_column。不新增 is_snapshot 等重复模型字段。辅助说明只解释“每天保存一份全量数据时启用”，不在普通配置文案中展开查询执行规则。
