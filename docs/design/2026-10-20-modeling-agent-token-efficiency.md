日期：2026-10-20。状态：已由 Claude review，用户于 2026-10-20 确认进入离线实现；不部署、不调用外部服务。

## 1. 范围与依据

本设计优化建模 Agent 的输入组织、工作步骤、技能和工具使用，不改变 `ontofoundry.proposals/v1`、core-1、Ossie 对齐原则或提案接受语义。依据当前工作区的核心模型设计、名称统一设计、使用方一致性修复设计，以及离线导出的运行清单、用量和四份 trace。仓库已有未提交改动，实施时须重新核对基线。

完整诊断为本轮 scratchpad 中的 `token-diagnosis.md`，不入库。下文用任务 ID 和事件 ID 保留证据索引，不复制运行凭据。所有业务例子采用虚构的“云帆商贸”和 `demo_orders`、`demo_refunds` 等表名。

明确边界：本轮实现输入组织、技能、脚本及离线测试；不调用 DataAgent、DeepSeek 或其他外部服务，不提交、不部署，不修改契约、核心模型或迁移。

## 3. 根因和约束

### 3.1 首要根因是理解格式的循环，没有推进与退出条件

技能要求先读 Schema 和核心 references，却没有把“够用即可生成”变成可执行步骤。Agent 在已读取业务输入后多次宣称掌握结构，仍继续枚举 `$defs`。缺少 Mapping、规则、指标等完整最小示例，使它把学习契约当成任务主体。

另一个独立根因是不可表达的请求未及时退出。失败任务要求退款金额来自退款 Dataset、销售额来自订单 Dataset，同时要求退款率为 ratio。现行设计 §3.6 要求两分量来自同一 Dataset。T13 已识别此冲突，推理中“退款率”出现 23 次，后续却转回 Schema。不能用“JSON Schema 没拒绝”推翻业务语义，也不能把退款明细与订单简单 JOIN 后求和：一单 100 元、两笔退款 10/20 元会把销售额复制为 200 元，把 30% 算成 15%。

### 3.2 上传、工具结果与历史请求是三种不同开销

`api/agent_conversation.py` 在每次用户发起建模时上传固定上下文、Schema 和适用的 MCP 配置；材料已有上传去重。不是每个 Pi 推理轮都重新上传文件。Pi 各轮请求携带对话及工具结果历史，所以减少工具往返同时减少历史重复输入。

当前平台 50 KiB 读取提示只覆盖材料／快照；Schema 未包含在此策略里，而且运行时 16 KiB 就折叠。单纯把所有文件一次 cat，会更早触发折叠。应批量读取“小而确定的必要输入”，并在源头限制 stdout。

### 3.3 运行时已有机制，但不能视为免费兜底

只读核对相邻仓库 `dataagent-runtime-pi/src/`：

- `kernel/cell.ts` 使用默认 16 KiB 工具折叠阈值、`CompactionSession` 和默认 64,000 的上下文估算预算；工具执行顺序运行。批量调用能减少模型往返，不保证工具并发。
- `context/compaction-session.ts` 使用序列化 UTF-8 bytes/3 估算，高水位默认 90%、目标 70%；默认触发约 172,800 B，包含消息结构和推理文本，不等于供应商实际 tokens 达 57,600。压缩代际固定前缀，代际内只追加，跨代仍可能损失缓存。
- `context/result-store.ts` 将 limit 上限钳到 100；普通文本 offset 按字符，实际最多取 limit×100 字符。模型传 400/500 并非取得相应行数；应优先读取源文件的指定定义／行，避免再次折叠召回内容。
- `core/pi_runtime.py`、`core/task_executor.py` 已传递 Agent 的 `max_turns` 和模型配置的 `max_output_tokens`。当前平台 deliver 只传 Agent 引用，没有每轮 token 预算接口。
- 输出上限设计与实现规定长度截断为 `PI_OUTPUT_TRUNCATED`。降低上限可能在调用写文件工具之前截断；不应简单把上限降到 4,096。

以上为本地当前源码机制，并不能证明失败当天部署版本和配置完全相同。缓存原因只能形成较强假设：长推理／大召回推动压缩，压缩改变历史前缀；需运行时补观测验证。9 月的治理设计有旧水位与原生模型摘要设想，以当前实现为准，不引入模型摘要步骤。

## 4. 拟议工作流程

### 4.1 有界的五步流程

1. **一次读取必要输入**：从已知技能入口读取简短指引、输入清单及本轮工作包；小材料批量带原始行号读取。不得目录遍历、读取环境变量、猜技能路径、通读无关 references 或扫描整个 `$defs`。技能无法加载时报告部署错误，禁止全盘搜索自救。
2. **语义预检和业务计划**：确认已有元素复用、引用依赖、证据定位、数据集及指标可表达性。预算 1 轮；不可表达的单项不出提案，继续合法范围并在最终中文说明列出原因和建议；用户要求“不要追问”同样适用，不静默改口径。只有实际缺少必须由用户决定的业务信息才使用 needs-input。
3. **一次写完整结果**：预计在 T4 前启动写入。使用辅助脚本填固定头、读取 update/delete 的 before 和 hash、合并 items；Agent 只提供业务内容及引用。大结果可先写若干本地片段，在同一个工具回合合并和检查，保持单一最终文件，不向模型回显全文。
4. **完整检查和定点修正**：首次生成后运行 `check_result.py --schema … --context … result`；同一命令输出计数及短错误。最多两轮修正，每轮只读报错路径与所需示例，整批复检。平台已有拒收后自动修复也计入同一修正预算，不能各自重置次数。
5. **完成即停**：检查通过即给简短中文业务说明；无追加探索、清理或重读结果全文。检查未通过不得伪装成功或上传半成品；耗尽修正预算使用既有失败路径。只有业务信息缺失才写 needs-input，格式错误不能转嫁给用户回答。

推荐正常路径 6–8 个模型轮次，修正后最多 10；Agent 硬上限已设为 12，留异常退出余量。提示中的步骤上限是软约束，真正硬限制依赖 DataAgent 配置。中间片段写在工作区内，最终文件临时写入并在检查通过后原子替换，避免平台消费半写文件。

### 4.2 质量要求

保持全部用户已明确范围、业务规则、证据和引用校验。复合业务标识不被误设为单列唯一，物理键顺序与业务标识分开；会员可空不被改为必填；不可从物理可空推翻业务“每位会员一家开卡门店”的含义。Schema 速查不能取代跨元素语义规则。

不为减少轮数删除困难元素、减少证据或改口径；无法表达时准确报告。不可表达的单项不阻断其余合法内容，无需事先授权；最终说明明确列出未交付项、原因及补充共同数据集等建议，不新增持久化状态。

## 5. 输入、技能和脚本设计

### 5.1 输入分成模型工作包与校验文件

| 文件／内容 | 模型如何使用 | 校验如何使用 | 预算与保真要求 |
| --- | --- | --- | --- |
| 简短技能入口、写法速查 | 首轮读；索引只指向本任务涉及的示例 | 示例在 CI 中按当前 Schema 检查 | 合计目标 ≤12 KiB；通用语义红线不能省 |
| 各类最小示例 | 九类 target、create/update/delete；Mapping、证据、simple/ratio/expression、规则分支分文件按需读 | 每例加虚构结果头／固定上下文，跑完整检查及服务端最终图校验 | 本轮选中示例目标 ≤8 KiB，不一次读所有例子 |
| 本轮输入索引／工作包 | 材料 ID/hash/bytes/总行数／范围、六 Dataset UUID 和列、已有元素摘要、适用示例、结果路径／头 | 从原固定上下文确定性派生 | 同规模 ≤8 KiB；是临时输入，不是核心字段或持久化摘要 |
| 完整固定上下文 | 保留可寻址文件；update/delete 精确读取目标和依赖，不强制整份进入上下文 | 必须用完整文件核对 before/hash/头 | 不删元素，不能只给局部草稿却声称完整校验 |
| 原材料 | 小文件一次读齐带原行号；大文件按结构与任务范围选取 | 原文件、原 SHA256、原行号及引文仍用于最终证据检查 | 本例两份仅 7,351 B，原样保留；不需要预裁剪 |
| 完整 Schema | 只给检查器；未覆盖报错定点查正例，仍无正例则交付合法范围并说明缺项，不读定义或遍历 Schema | 每轮完整 Schema 仍上传，检查脚本读取 | 本例上传开销不变；省的是进入对话和多轮历史重放 |
| MCP 配置 | 默认不读；固定上下文缺信息时由工具读取，永不打印 headers | 沿用固定版本和权限 | 本例已有六 Dataset 无额外查询必要；不取消读取能力 |

大材料预裁剪只建立本轮派生片段，不覆盖原文件；保留原材料 ID/hash、原行号范围和遗漏范围索引。禁止改写、重新排序后把片段行号冒充原行号。对象／字段选择不能用简单关键词过滤漏掉继承、反向关系、依赖或同名对象。完整上下文仍给检查器，必要时定点扩展工作包。

输入工作包、速查和示例属于本项目自创的执行优化，不来自 Ossie/Fabric IQ/Foundry 的核心模型概念；删除它们只影响效率，不丢业务语义。不会将关联、计数或摘要存入模型。不新增契约字段、业务状态、Schema 版本或 Alembic 迁移。完整校验使用既有结构即可。

### 5.2 稳定前缀

将稳定的系统指令、技能版本、通用写法与工具定义放在前；动态 run_token、固定头、材料清单和用户消息放在后。相同输入排序稳定、序列化稳定；不要把每轮变化的时间、路径或凭据插入通用指令中。

这只能改善可复用前缀，不保证跨任务或供应商缓存命中。新建模任务仍有不同固定上下文；跨轮保持历史追加及压缩代际稳定需要 DataAgent 配合。不得删除 run_token／hash 或复用上次结果头来追求缓存。

### 5.3 技能结构和错误格式

- `SKILL.md` 改为执行清单、语义红线、退出标准和 references 路由；不要求每轮通读完整 Schema、模型或全部模式。
- `core-model.md` 保留业务约束，在速查中显式给出 Mapping.fields 使用属性 name、source_id 是局部来源 ID、ratio 同 Dataset 等高频疑问。外部交换、继承、导入补全仅被相应任务触发。
- 示例应完整可运行，覆盖同批引用、depends_on、数据映射、复合键、可空会员、证据、人工证据保留、更新删除与跨数据集比率不出提案并说明建议。示例是写法依据，Schema 和现行设计仍是规范来源；自动校验防止漂移。
- `check_result.py` 保留当前全部校验和失败退出码；按 target_kind/operation 和 discriminant 选取相关 oneOf 分支错误，输出 JSON Pointer、item client_ref、错误代码、期望和实际类型、对应示例。例：`/items/7/after/fields/customer_code/source_id：来源 "aux" 未声明；本映射可用来源 ["main"]`。该例的语义检查需明确实现，不能声称现有脚本已经覆盖。
- stderr/stdout 摘要目标 ≤4 KiB，完整错误写工作区文件；摘要包含总错误数、被省略数和如何取指定 item，不能通过截短改变“不通过”结果。默认不回显整个失败实例或复杂 oneOf 树，不打印材料／配置原文。原异常、读文件失败也要给短的可操作错误。
- 可增加离线 `prepare_result.py`（暂定名），提供固定头、操作封装、从固定上下文提取 before/hash、合并片段和重复引用检测；不推断字段业务含义、生成证据、自动补语义默认值或擅改指标类型。只生成新增 client_ref，不生成最终业务 UUID；Schema 和所有现有校验照跑。

## 6. 工具与 DataAgent 配合建议

本仓库可完成：已知路径、输入清单、批量小输入、按定义定点读、stdout 字节限制、完整错误落盘、写后检查、修正计数传播、技能示例与生成辅助工具。工具若返回折叠指针，先回到源文件按所需路径抽取；不能在同一 Schema 结果上连续分页“学完”。单次 stdout 建议 ≤8 KiB（给 16 KiB 折叠阈值留封装余量），超限返回范围索引，绝不静默丢数据。Bash 原始捕获丢字节与 result_ref 可恢复折叠须分别识别。

DataAgent 建议，单独评审并由已有 Agent 的管理员配置／发布，不在本仓库实现：

1. **已完成**：Claude 已在已有建模 Agent 设置并发布 `max_turns=12`（用户于 2026-10-20 确认）；用正常／修正／阻断三类离线用例校验状态归类。先不降低共享模型输出上限；如有 Agent 独立覆盖能力，可在离线产物尺寸证明充足后试用单轮 16,384，需包含推理和工具调用 JSON。平台目前未暴露此覆盖能力，不假定可直接设置。
2. 增加每任务累计输入／未命中／输出预算及工具回合预算，达到软水位先要求收敛，硬水位确保产物检查和明确失败。仅提示词不能严格执行；不把供应商输出上限当累计预算。
3. 记录发送前消息 bytes、估算 tokens、压缩 generation/前后 bytes、脱敏前缀 hash、有效输出上限、缓存用量及折叠次数；不记录凭据。用这些证据定位缓存回退，不能承诺稳定前缀可消灭所有失效。
4. 在既有 sticky compaction 上验证缓存稳定性；不简单关闭治理／提高窗口，也不调高折叠阈值让 Schema 全文进入。文本召回工具明确字符单位、实际钳制后的 limit 和下一 offset，防止分页理解错误。

### 7.2 衡量目标

同规模指六个已登记 Dataset、两份小材料、六类对象／关系／映射、规则及契约可表达的指标，模型与技能版本固定，不复用旧产物。非阻断输入：

- 正常 ≤8 轮，含修正 ≤10 轮，开始写结果 ≤T4，修正 ≤2 轮；Agent 硬上限已设为 12。
- I≤180,000，U≤40,000，O≤25,000（包含供应商计入的推理和工具输出生成）；C=I−U，不以缓存率单独判成功。
- Schema fetch/search=0，环境／越界探索=0；工具折叠目标 0，例外须能解释；每次 stdout≤8 KiB，错误摘要≤4 KiB。
- 首轮静态可读输入预算 bytes/3≤12,000（含已知系统／技能／工作包／选中示例／材料，工具定义另核算），随后必要新增可读内容预算≤8,000；这是代理指标，不等于 DeepSeek 精确 tokenizer。
- 必须生成有效非空提案，覆盖确认范围；Schema、上下文、引用、最终图和证据校验全部通过，不能以缩减范围换达标。跨 Dataset ratio 不出提案，在最终中文说明列出原因和建议，合法分量照常建 simple 指标；不要求先追问，也不静默改变公式。没有任何可表达内容时沿用既有空批次／失败行为，不新增状态。

### 7.3 不消耗模型的验证

实施轮统一完成编辑后执行：输入上传与实际选中内容分开统计 bytes、字符、行数，以 bytes/3 为中心、bytes/4–bytes/2 为敏感区间；已安装匹配 tokenizer 时额外精确统计，无需下载或 API。记录模板、技能、Schema 内容 hash，捕获完整系统和工具定义预算，未知部分标为未知。
