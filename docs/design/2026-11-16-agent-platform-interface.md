# 智能体与平台接口：一条变更管线，技能做薄

日期：2026-11-16。状态：讨论中，第 2 节为用户已定的方向。来源：用户 2026-11-16 提出三个问题——人工与智能体的工作阶段不同，是否应统一；检查是否应全部在接口里，让技能成为薄层；智能体知道接口 schema 后，技能里的示例是否还需要。要求不过度设计，高内聚、低耦合。评审：Gemini 4 Argon（high、medium 各一份，`~/.agents/handoffs/2026-11-16-gemini-agent-interface-arch*/`），Claude 核对源码后合并。

## 1. 现状与问题

| | 人工 | 智能体 | 导入 |
|---|---|---|---|
| 入口 | `POST /element-saves`；或 `PUT /sessions/{id}` 存草稿后发布 | 技能 `prepare_result.py` → `POST /ontology/workspaces/{w}/runs/{run_token}/proposals` | 导入确认 → 提案 |
| 阶段 | 元素保存：编辑 → 校验 → **立即发布**（会话外也可） | 提案 → 接受进草稿 → 发布 | 同智能体 |
| 检查 | 图校验、连接列、发布检查 | 技能本地检查 → 提交检查 → 接受时检查（AC-02～11）→ 发布检查 | 提交、接受、发布 |

问题：

1. **同一份模型，两套标准。** 接受时规则不作用于人工保存：人工可以直接发布“已绑定表但属性没有列”的对象，智能体同样的提案接受不了。
2. **技能重写平台逻辑。** 约 3 700 行 Python 中，约 790 行重做提交检查（`check_part.py` 226、`check_result.py` 395、`column_refs.py` 109、`function_refs.py` 56＋生成的函数清单），只为不浪费提交轮次（`REPAIR_LIMIT` = 3）；另有平台逻辑的副本：`materials.py`（按行号补引文）、`expand_tables.py` 的物理类型映射、`show_element.py` 的表达式分词与反向引用，靠 `tests/test_platform_copies.py` 维持一致。接受时规则在技能里完全没有。
3. **示例与 schema 重复。** 50 个按类型、按操作的小示例（53 KB）与智能体必读的 `extract-kit/` 大量重叠；`extract-kit/05.json`（实例）为空。
4. **智能体在运行中读不到平台。** 技能说明里 MCP 只供提交使用（`init_workflow.py:251`），所以平台把整份草稿和分页索引上传给它，由 `show_element.py` 在本地重新解析。

## 2. 决定（用户 2026-11-16）

| 编号 | 决定 |
|---|---|
| AI-01 | **一条写入管线。** 人工保存、智能体提交、导入都表示为同一种变更集（`items[]`），经同一服务检查、写入。人工保存在 API 层自动转成一批提案并立即接受；前端编辑器不改，仍提交编辑后的草稿，由后端算出变更项（`element_save` 已能算出改动范围）。 |
| AI-02 | **保存不发布。** 所有保存都只进草稿；发布按钮旁显示有内容待发布（如“3 项待发布”），由用户点发布。取消“元素保存即发布”。 |
| AI-03 | **会话外的保存进虚拟会话。** 在本体对象等页面（不在构建会话里）保存时，写入该用户在本工作空间的虚拟会话（如“我的修改”），按需自动创建。它就是普通会话：出现在会话列表中，可以对话、建模、审提案；它的草稿就是该用户“待发布的修改”。智能体在该会话运行期间，草稿按现有规则不能编辑，保存时提示等运行结束。 |
| AI-05 | **智能体可以审人工修改。** 运行输入增加“本会话未发布的修改”（会话页已有的 `base_diff`，`element_changes(基线, 草稿)`），人工修改按 AI-01 带有保存人和时间。用户在会话里请智能体检查，智能体在回答里说明；需要改的，以提案形式给出，由用户接受或拒绝。不新增模式或按钮。 |
| AI-06 | **人工修改在发布前可撤销或退回待审。** 人工保存是已接受的提案，现有“撤销”（拒绝已接受的提案，草稿复原，依赖它的一并拒绝）直接可用。新增一个动作“退回待审”：撤销并回到待审，修改离开草稿但留在列表里，可以先请智能体审。人工保存的批次在发布前一直可以决定，不因会话里开始新的智能体运行而变为只读（现有规则只对智能体批次保留，`services/session_gate.py`）。发布后修改已进入版本，要改回就再保存一次，产生新的修改。 |
| AI-04 | **接口按会话寻址。** 运行凭据已含工作空间、会话、运行和用户（`services/run_credentials.py`），路径里的 `run_token` 是重复信息。改为 `POST /workspaces/{w}/sessions/{s}/changes`：人工用登录身份，智能体用运行凭据；运行只在凭据里，继续承担重试回执、过期运行拒绝和提交轮次。技能从运行输入里的 `submit_url` 取地址，不拼路径，改路由不影响技能。 |

## 3. 设计

### 3.1 管线

```
变更集 items[]（人工保存 / 智能体提交 / 导入）
  → 检查：结构、引用、图校验、接受时规则 —— 只此一处实现
  → mode=check   ：只返回问题，不写任何东西
  → mode=propose ：存为待审提案（智能体、导入）
  → mode=apply   ：存为提案并立即接受（人工保存；审阅时的接受走同一步）
  → 草稿（构建会话或虚拟会话） → 用户点发布
```

人工保存的提案按生产者标为“手工保存”，在提案面板“已接受”中可区分，不新增状态；修改历史因此统一为“谁、何时、接受了什么”。

### 3.2 检查模式（`mode=check`）

- 与提交同一路径，但**不写任何东西**：现有提交会把“表结构收据”写成材料文件并入库（`services/table_submission.py:131`），检查模式只在内存中计算，数据库回滚清理不了磁盘文件；
- 同时运行接受时规则但不阻止，返回每条提案的 `acceptance_issues`，智能体可在提交前补好；
- 支持**部分批次**：技能分片写作，检查时允许引用尚未写出的片段，未闭合引用列为待定而非错误（现由 `check_part.py` 本地处理）；
- 不计提交轮次；正式提交仍限 3 轮。

### 3.3 技能变薄

| 处置 | 文件 | 行数 | 由谁接手 |
|---|---|---:|---|
| 删除 | `check_part.py`、`check_result.py`、`column_refs.py`、`function_refs.py`＋函数清单生成 | 约 790 | 检查模式 |
| 删除 | `materials.py` | 40 | 平台按行号补引文 |
| 删除副本 | `expand_tables.py` 的物理类型映射、`tests/test_platform_copies.py` | 约 50 | 平台在表结构文件里给出每列的值类型 |

| 以后 | `show_element.py` | 310 | 运行中可读平台（MCP 读本轮草稿），届时删除 |

### 3.4 示例

schema 说明允许什么，教不会怎么建模（新对象与新属性用 client_ref 互相引用、更新只写 target_id、映射表达式等），示例仍需要，但只留一套：

- 保留 `extract-kit/`，补齐 `05.json`（一个文档实例、一个关系实例）；
- 未覆盖的少见写法（映射表、表达式绑定、继承、派生）合为一个变体文件；
- 删除 `examples/` 下按类型、按操作的小示例和 `catalog.json`；
- 平台检查的报错直接给出期望字段形状，省去报错后再查示例；
- 所有保留示例在测试中经检查模式通过。

## 4. 实施顺序

1. 检查与写入管线：`/sessions/{s}/changes` 三种模式，提交路径改用它；旧 `runs/{run_token}/proposals` 在过渡期转发。
2. 人工保存改走 `mode=apply`，取消保存即发布；“退回待审”与人工批次发布前可决定（AI-06）；发布按钮旁显示待发布数量；虚拟会话（会话列表可见、可对话）；运行输入增加本会话未发布的修改（AI-05）。
3. 技能改用检查模式，删除第 3.3 节所列文件，示例按 3.4 精简。
4. 用 DeepSeek 复跑验证（与 `2026-11-15-accept-completeness.md` 第 10 节一起），比较轮次、修正次数和输出 token。
5. 以后：运行中经 MCP 读本轮草稿，删除 `show_element.py` 与平台的分页索引上传。

## 5. 待确认

1. 虚拟会话的范围：按**每个用户在每个工作空间一个**设计（2026-11-16 用户补充 AI-03、AI-05 时按此理解）。共用一个会把多人的未完成修改混在一起；多人的修改在发布时按现有三方合并处理。
2. 人工在构建会话里保存，进该会话草稿；在会话外保存，进虚拟会话。两者同时有未发布内容时，发布按钮分别显示，各自发布。
