## 1. 依据与边界

## 3. P0 请求与状态生命周期

href 依赖工作空间 ID 和 URL 中的 session 默认值；open 依赖 href 和 navigate。显式 sessionId（含 null）优先于 URL，避免稳定引用掩盖旧工作空间或旧会话。

每个请求面板接收页面激活与页签可见的合取信号。实例列表的防抖定时器隐藏时清理，已发请求的成功/失败/结束回调失效；关联实例读取也受同一信号管理，返回页签时可以重新读取未完成选中项，不留下永久加载状态。请求范围区分工作空间、元素、版本与会话 revision，版本更换重新挂载相关面板，防止相同查询字符串误用旧结果。指标预览、数据集校验/预览及连接元数据读取遵循相同边界，数据集切页签仍沿用原来的非保活布局。

不要求底层网络必然中止：即使请求已经到达数据库，前端也只丢弃响应，不声称能撤销已执行 SQL。接口继续从 api/client.ts 调用，无 REST、Schema 或数据库变化。

验证跨页签修改统一保存、取消恢复、409 后修改保留、隐藏不新增列表/预览请求、迟到成功与错误均丢弃、关闭重开和换元素/版本清理状态。保留背景图谱缩放与选择，1440×900 检查表格返回/展开后的布局和浮层。

## 4. P1 固定版本共享读取

当前成员路径 modelingApi.snapshot 下载 latest 定义后串行 withInstances；详情先读取 workspace.version_id，再读取 latest，可能将 v7 元数据与 v8 定义组合。本体视图的 overview 与 model 也存在同类窗口。

统一流程：取得当前指针或 overview.version.version_id → 读取该 ID 的 presentation → 共享只读定义及一次构建的前端索引 → 按需独立读取当前实例。旧 published-snapshot 作为兼容入口保留，新消费者不再依赖它。presentation 当前前端丢弃实例字段，独立实例不得写回共享定义；编辑器组合独立草稿时明确来源。会话草稿和待发布预览仍使用现有 session/revision/preview hash，不混入发布版本缓存。

共享键至少包含主体、认证/授权代次、workspace_id、version_id、授权投影和表示版本。同键合并进行中的 Promise，缓存解析后的只读对象；失败立即移除，消费者退出不取消其他消费者需要的共享请求。编辑时复制基线成独立草稿，开发环境可冻结共享对象以发现污染。LRU 估算内存并记录在用对象和缓存占用，不能声称条目上限就是字节上限。

发布只改变 current 指针，新版本新键，旧版本仍有效；登出、切账号、权限变化清空对应缓存并阻止旧请求回填。指针校验和请求返回版本 ID 都必须核对。权限变化的服务器鉴权始终有效，前端缓存不能替代授权检查。

P1 不需要新业务字段；api/client.ts 的 presentation 响应、api/types.ts 的只读定义边界及调用者需要同步梳理。实例读取依赖当前版本：若实例响应 version_id 与固定定义不同，不能静默混用；推荐提示刷新而不自动切换未保存编辑，此交互归 D6 确认。

## 5. P2 服务端索引缓存和条件请求

扩展 services/read_cache.py 和 domain/graph.py 的 DraftIndex。每份发布版本缓存规范化模型、ID 查找、属性/规则归属、父子、双向关系邻接，以及有效继承属性、规则、映射等纯版本派生。按目标祖先链访问，避免每次有效属性读取扫描全空间。自关联去重、继承顺序和标识列 UUID 顺序保持现行语义。

服务端键包含 workspace_id、version_id、规范化内容哈希及派生实现代次。纯索引可在鉴权后的不同投影间共享；授权后的表示另加投影/权限键，避免泄露成员映射。会话缓存继续用 session ID、revision、draft hash，提案派生还含提案状态。缓存不保存 ORM 对象或 DB Session，不修改共享结果，返回可变结构前复制或构造投影。

增加同键并发计算合并、异常广播并移除失败条目，计算在全局锁外；补估算字节 LRU、命中/未命中/合并/驱逐和耗时指标。继续进程内多 worker 独立预热，不引入分布式缓存。

resource_items 不能整体按版本永久缓存：binding_status、relationship_binding_status、数据集投影依赖当前连接和登记元数据；这些状态在请求边界重新读取，或另用元数据代次键。实例、样例、数值预览和证据访问权限单独读取。固定定义即使不变，权限或元数据变化也必须得到新结果。

HTTP 策略：当前指针和固定版本授权表示初期均采用 `Cache-Control: private, no-cache`；逻辑表示使用弱 ETag，覆盖版本、规范化内容身份、授权投影/权限代次、表示实现版本。若响应含动态元数据，要么拆分响应，要么将其代次纳入校验器；无法轻量确定时不提前返回 304。version.sha256 包含快照与校验报告，不当作响应字节哈希；normalized_snapshot_sha256 也不等于响应字节哈希。

先鉴权并验证工作空间版本归属，读取轻量元数据并匹配 If-None-Match（含列表、弱比较及 `*`），再决定 304；命中不生成完整投影，仍返回 ETag/缓存头，正文为空。200 的标签必须与实际表示一致。优先让浏览器处理 HTTP 缓存；若采用手动条件请求，必须同步改 request()，保存对应响应体、处理无本地实体的 304 重试，不能沿用把裸 304 当错误的逻辑。前端共享负责消除同会话重复请求，304 仍有网络往返。

## 6. P3 目录摘要、元素详情和契约

新增目录摘要读取（建议 `GET /api/v1/ontology/workspaces/{workspace_id}/catalog?version_id=…&kind=…&q=…&limit=…&cursor=…`），只返回授权摘要、计数、next_cursor 和固定版本信封。游标绑定版本、投影及筛选，稳定按 kind、技术名和 ID 排序，避免翻页跨版本。新增读取字段仅为 API 派生投影，自创执行优化，删除会增加传输与计算；已有定义可推导，不进入 core-1 或权威快照。

复用 `GET /types/{type_id}?version_id=…`：get_type 先在共享索引按 UUID 找到目标，再构造目标继承/引用闭包；兼容现有名称查找及 ambiguous/candidates，不调用全量 search_types。属性和规则先定位所属对象/关系，维持原跳转。对象一次返回有效字段、关系、规则和必要引用摘要，不按四个页签机械拆请求，不返回全空间实例；极端高关联度后续依据实测设计分页。保持原响应兼容，确需改变详情形状时新增显式表示版本，不能静默删除旧字段。

MCP 在工具分派之后才读取所需上下文；search_ontology、ID 批读与 REST 使用相同版本索引和权限投影。只按目标计算，同时保留原分段/大小预算、名称歧义、继承和工具响应兼容性。依赖当前连接的投影在返回边界补充。

读取详情不能伪装成完整 Draft 送回保存。进入编辑时加载固定版本完整共享基线并复制，保持预检、影响确认和 CAS；聚合写入新契约不在本计划。
