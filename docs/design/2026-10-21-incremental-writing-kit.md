# 增量与小改动写法包

## 已确认决定

沿用用户明确的离线范围：不调用模型、DataAgent 或外部服务，不部署、不提交；全部编辑完成后统一验证。新增入口是自创执行优化，服务于查找和写提案，不引入模型字段、状态、契约或迁移；删除入口只损失执行效率，全部业务语义由现有模型表达。

## 设计

- `show_element.py --work-pack <工作包> <英文标识或id>...` 读取工作包指定的 context_file，只按 UUID 或英文标识精确匹配。支持 `kind:标识`、`实体.属性/关系`；同名返回确定的候选写法，不按 display_name、相似度或材料猜测。输出完整定义、固定 hash 与直接引用者的 id/英文标识，引用从现有结构字段推导，不持久化反向索引。
- 输出按 UTF-8 限制为 8 KiB。超过上限不截断定义：给出确定的 `--page N` 调用，每页输出完整 JSON 文本的可无损拼接片段；分页绑定内容摘要，防止上下文变化混读。错误及候选也走同一有界输出路径。
- `show_example.py --part update` 提供更新数据集补列、已有实体映射、表达式事件数据集与 simple/ratio 的裸数组；`--part edit` 补充属性/指标名称说明修改、已有 owner_id 引用与 delete。两个片段配同一固定 v1 context，可合并验证。update 的 after 为完整定义（去 id），保留证据与未改字段；before/hash 由 prepare_result 自动填写。
- 复用星河零售保守 63 项接受后得到固定 v1 模型；与完整 69 项图比较时只归一 UUID，不丢语义字段。退款增量 1 update＋6 create，由新入口与精确查询结果提供依赖；SQLite 按最终增量图的事件 SQL 和指标定义复算退款率。
- 小改动直接走增量路线，不读 context 全文、脚本源码或 Schema；首读统计含提示、工作包、材料、已同步表、原则、增量指南、取值、写法与查询输出。SKILL ≤4,000 B，单次 ≤8 KiB。预计轮数只作路径估计，不声称模型运行成功。
- display_name 只写名称，说明写 description；不自动推断或重写用户名称。

## 验证

CI 覆盖精确、歧义、不存在、反向引用、分页重组、固定 hash、增量双入口三层校验、7 项最终图一致性和退款率 10.72%；全部编辑后运行后端、技能、ruff、预算四项。

## 完成结果

增量首读 44,385 B（包含 17,307 B 全部索引页、5,356 B 两组查询输出），上限 50,000 B；可选 edit 另加 1,413 B。SKILL 3,858 B，增量最大单次 5,919 B；全量抽取 35,982 B，计划 18,261 B，既有预算仍通过。正常 6–8 轮，两次修正 10–12 轮，仅为路径估计。统一验证：后端 1045 passed／17 skipped，技能 216 passed，ruff 通过，all_limits_pass=true。七项最终图与 69 项完整预期一致，SQLite 退款率 10.72%；未调用模型或外部服务。

## 写法包与验收场景分离（2026-10-21 已确认）

用户确认写法包与验收场景分离。本次选择虚构的澄页图书馆借阅领域，覆盖借阅单、借阅明细、押金与赔偿；与零售无关，仍能表达复合标识、关系、映射和两类独立日期事件。星河零售材料及保守版、补列版、v1 七项增量仅留在 tests/fixtures/extract-retail，作为离线证明输入与预期。原包包含验收答案，会让真实验收无法证明独立建模，因此不能继续用于验收；真实验收须在换包后重跑，本次只做离线验证。

通用 examples 的非协议示例同步换域，协议模板保留。新增防泄漏测试从零售夹具的语义标识、物理表列、中文名称及验收材料提取集合，对包内全部文件、公开 show_example 输出和非协议示例比较；通用词例外显式列出并解释。图书馆增量使用独立 v1，上下文和验收夹具无绑定；零售作者测试只借用包的字段形状，业务内容在测试内构造，仍核对完整最终图与 SQLite 数值。上限不变，超预算优先压缩示例。没有新增模型概念、契约或部署步骤。
