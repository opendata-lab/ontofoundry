# 用户管理与空间公开（按用户名识别用户，对齐 Superset）

日期：2026-11-12。状态：已确认。来源：管理员需要在用户首次登录前建好账号并分配工作空间，登录后直接拥有权限；做法沿用 Apache Superset（Flask-AppBuilder 5.3）：用户按用户名识别，管理员预先建用户，SSO 登录按用户名匹配到同一用户。

空间公开设置参照飞书文档“组织内获得链接的人可阅读”：空间可设为公开，所有登录用户都能阅读。

依赖[平台登录](2026-11-12-platform-login.md)，替代其第 5 节的用户主体规则。实施见[计划](../plans/2026-11-12-user-management-plan.md)。

## 1. 现状

- 用户按 `users.subject` 识别，值为 `local:<username>` 或 `<provider>:<sub>`，本地账号和 SSO 账号即使同名也是两个用户。
- 空间管理员按 `subject` 添加成员，对方必须先登录过一次（“用户尚未登录过平台”）。
- 没有平台管理员，没有跨空间查看用户的地方。

## 2. 决定

| 编号 | 决定 | 状态 |
|---|---|---|
| UM-01 | **用户名即用户**：`users.subject` 改为 `users.username`，全平台唯一，不区分大小写（同 Superset 默认 `AUTH_USERNAME_CI=True`）。本地登录取 `LOCAL_USERS` 的 `username`；SSO 登录取钩子返回的 `username`，没有时取 `sub`。本地账号与 SSO 返回同一用户名时是同一用户，共享空间成员身份。来源：Superset `auth_user_oauth` 按用户名查找用户。 | 2026-11-12 用户确认 |
| UM-02 | **平台管理员（超级管理员）**：配置文件新增 `ADMIN_USERS`（用户名列表）。列表中的用户可进入“用户管理”，并在所有空间（含私有空间）拥有空间管理员的全部权限：阅读、编辑、空间设置、成员管理、公开开关、用户反馈。这一权限按配置推导，不写入成员表，不出现在成员列表，也不计入“最后一名管理员”。不入库，改配置后重启生效。来源：DataAgent `ADMIN_USERS`（DataAgent 按 `<provider>:<sub>` 匹配，此处按用户名，与 UM-01 一致）。 | 2026-11-12 用户确认；超级管理员 2026-11-12 用户决定 |
| UM-03 | **未预建用户自动创建**：SSO 或本地账号首次登录且用户名不存在时自动创建，没有任何空间成员身份，与现在一致（同 Superset `AUTH_USER_REGISTRATION=True`）。 | 2026-11-12 用户确认 |
| UM-04 | **用户管理首版**：用户列表（含所在空间和角色）、预建用户、为用户分配空间和角色。只有平台管理员能新建用户。不含停用用户、删除用户、改用户名。 | 2026-11-12 用户确认 |
| UM-05 | **空间公开／私有**：空间增加“公开”开关。公开空间对所有登录用户可见并可阅读成员能读的全部内容（本体、映射、材料、会话、实例），但不能修改；私有空间对非成员完全不可见。来源：飞书文档链接分享“可阅读”。替代原“非成员只读已发布本体”的规则。 | 2026-11-12 用户确认 |
| UM-06 | **默认值**：升级时已有空间全部设为公开；新建空间默认私有。 | 2026-11-12 用户确认，已知升级后非成员可读已有空间的映射、材料、会话和实例 |
| UM-07 | **外部智能体**：公开空间在网关中对非成员同样可见可读，令牌有 `mappings:read` 时也返回映射。 | 2026-11-12 用户确认 |
| UM-08 | **空间角色三档**：可查看（新增，存储值 `viewer`）、可编辑（即现有 `member`，存储值不变）、管理员（`admin`）。可查看成员能看到私有空间并阅读全部内容，不能修改；可编辑成员可建模、提交提案、维护映射、同步数据表和上传材料；管理员另可管理空间设置、成员、公开开关，以及新建、修改、删除数据连接和删除材料（这两项沿用现有的仅管理员规则）。空间管理员只能把已有用户加入本空间并设定角色，不能新建用户。来源：常见数据平台的查看／编辑／管理三档角色（如 Grafana Viewer／Editor／Admin）。 | 2026-11-12 用户决定 |

**风险（随 UM-01 接受）**：用户名由谁控制，谁就是这个用户。SSO 钩子返回 `admin` 的人会登录成本地 `admin` 这个用户，获得其全部空间身份；若 `admin` 在 `ADMIN_USERS` 中，也成为超级管理员，可管理全部空间。Superset 同样依赖认证服务给出的用户名可信。现场接入 SSO 前须确认钩子返回的用户名不会与本地账号冲突，或把本地账号改成 SSO 中不存在的名字（如 `ontofoundry-admin`）。

**升级影响（随 UM-06 接受）**：升级后，所有登录用户都能阅读已有空间的映射、材料、会话和实例数据，包括会查询业务库的实例页面。发布说明须提醒现场：不希望共享的空间，由空间管理员在升级后改为私有。

## 3. 用户识别

| 登录方式 | 用户名来源 | 显示名 |
|---|---|---|
| 本地账号 | `LOCAL_USERS[].username` | 已有用户保持不变；新建时为用户名 |
| SSO | 钩子返回的 `username`，缺省为 `sub` | 每次登录按钩子结果更新（取值顺序同平台登录第 4 节） |
| 预建 | 管理员填写 | 管理员填写；该用户之后 SSO 登录时被钩子结果覆盖 |

钩子契约增加可选字段 `username`（1～120 个字符，不含控制字符）。DataAgent 只读取它列出的字段，同一个 `custom_sso_user_info.py` 仍两边通用。

`dev` 模式的开发用户用户名为 `dev`，视为平台管理员（超级管理员），便于本地开发。

## 4. 配置

```python
ADMIN_USERS = ["admin"]   # 基础配置默认值；现场在覆盖文件中修改
```

校验：列表，每项为非空字符串；不要求对应用户已存在。列表为空时没有人能进入用户管理，启动日志输出警告。

## 5. 界面

**页头用户菜单**（点击页头用户名）：“个人中心”、“用户管理”（仅平台管理员显示）、“退出登录”。

**个人中心**（`/me`）：外部智能体接入设计第 4.6 节已定义的页面。本次只实现“个人信息”页签：用户名、显示名、邮箱、是否本地账号、所在空间及角色，只读。“个人令牌”页签随外部智能体网关实施。

**用户管理**（`/admin/users`）：不属于任何工作空间，沿用列表页布局（`PageHeader` 加 `Panel` 内的 Ant Design `Table`）。

| 列 | 内容 |
|---|---|
| 用户名 | `username` |
| 显示名 | `display_name` |
| 本地账号 | 用户名在 `LOCAL_USERS` 中时显示“是”（按当前配置推导，不入库） |
| 平台管理员 | 用户名在 `ADMIN_USERS` 中时显示标签（推导，不入库） |
| 所在空间 | 每个空间一个标签，只显示空间名；角色在“分配空间”抽屉中查看和修改。平台管理员显示“全部空间（超级管理员）” |
| 最近登录 | 时间；从未登录显示“尚未登录” |

- 按用户名或显示名搜索。
- “新建用户”：填写用户名（必填）、显示名（必填）、邮箱（可选）；用户名已存在时提示“用户名已存在”。
- 行操作“分配空间”：打开抽屉，列出该用户的空间和角色，可添加空间（下拉列出全部空间）、改角色（管理员／可编辑／可查看）、移除。不能移除或降级某空间的最后一名管理员（“该空间至少需要一名管理员”）。

**空间设置 → 成员**（空间管理员和平台管理员）：添加成员改为按用户名搜索已有用户（含预建但未登录的用户），选择角色“可查看／可编辑／管理员”，不再要求对方先登录；搜不到时提示“用户不存在，请联系平台管理员在用户管理中创建”，空间管理员不能在此新建用户。成员列表可改角色、移除，遵守最后一名管理员规则。

**空间公开**

| 用户 | 公开空间 | 私有空间 |
|---|---|---|
| 平台管理员 | 与空间管理员相同 | 与空间管理员相同（目录中可见全部空间） |
| 管理员、可编辑成员 | 不变 | 不变 |
| 可查看成员 | 阅读全部内容，编辑按钮隐藏，写接口 `403`，看不到“空间设置”和“用户反馈” | 同左 |
| 已登录非成员 | 目录中可见，标“公开”；左侧菜单显示成员可见的全部阅读页面，所有编辑按钮隐藏，直接调用写接口返回 `403`；看不到“空间设置”和“用户反馈” | 目录中不显示；直接访问地址显示“无权访问” |

- 开关在“空间设置”中，空间管理员和平台管理员能改。
- 公开不等于成员：非成员不出现在成员列表，不能建模、提交提案、修改映射或连接。数据连接对非成员显示连接信息，密码与现在一样从不返回。
- 改为私有立即生效：非成员下一次请求即得到无权访问。

## 6. 数据与接口

**表结构**（Alembic 迁移）：

- `users.subject` 改名为 `username`，唯一索引建在 `lower(username)` 上。
- 新增 `users.last_login_at`（可空），每次登录成功时写入。
- 新增 `workspaces.is_public`（布尔，非空）：迁移时已有空间为 `true`，之后新建默认 `false`。
- 已有数据：去掉 `subject` 中第一个 `:` 及之前的前缀（`local:admin` → `admin`，`internal:u123` → `u123`）；`dev:admin` 改为 `dev`。去前缀后出现重名时迁移失败并列出冲突用户名，由现场处理后重试。

**接口**（`/api/v1/admin/*` 要求登录会话且当前用户在 `ADMIN_USERS` 中，否则 `403`）：

| 接口 | 说明 |
|---|---|
| `GET /api/v1/auth/me` | 增加 `username`、`is_platform_admin`、`local_account` |
| `GET /api/v1/me/workspaces` | 当前用户的空间及角色（个人中心用） |
| `GET /api/v1/admin/users?q=` | 用户列表，每项含 `id`、`username`、`display_name`、`email`、`local_account`、`platform_admin`、`last_login_at`、`workspaces[{id, name, role}]` |
| `POST /api/v1/admin/users` | `{"username", "display_name", "email"?}`；重名 `409` |
| `GET /api/v1/admin/workspaces` | 全部空间 `[{id, name}]`，供分配下拉框 |
| `PUT /api/v1/admin/users/{user_id}/workspaces/{workspace_id}` | `{"role": "admin" | "member" | "viewer"}`，加入或改角色 |
| `DELETE /api/v1/admin/users/{user_id}/workspaces/{workspace_id}` | 移出空间 |
| `GET /api/v1/workspaces/{id}/users/search?q=` | 空间管理员添加成员时搜索用户，返回 `id`、`username`、`display_name` |
| `POST /api/v1/workspaces/{id}/members` | 请求体由 `subject` 改为 `user_id`；`role` 增加 `viewer` |
| `PATCH /api/v1/workspaces/{id}/members/{member_id}` | 改角色（新增）；空间管理员或平台管理员 |

| `GET /api/v1/workspaces` | 平台管理员返回全部空间；其他用户只返回成员空间和公开空间；每项增加 `is_public`，非成员的 `role` 为 `null` |
| `PATCH /api/v1/workspaces/{id}` | 请求体增加 `is_public`，空间管理员或平台管理员 |

**权限**：`services/access.py` 集中三个判断，平台管理员三项都通过：

| 判断 | 通过条件 | 用于 |
|---|---|---|
| `can_read_workspace` | 任一角色成员，或空间公开 | 所有读接口（本体、映射、材料、会话、实例、数据连接、导出、概览） |
| `can_edit_workspace` | 可编辑成员或管理员 | 所有写接口（建模、提案、映射、连接、导入、发布），替代现有 `require_member` |
| `can_manage_workspace` | 管理员 | 空间设置、用户反馈、成员管理、公开开关 |

网关的成员检查改为 `can_read_workspace`；`list_spaces` 的角色为 `admin`／`member`／`viewer`，非成员的公开空间为 `public`，平台管理员的非成员空间为 `admin`。`mappings:read` 仍按令牌权限控制。平台管理员的个人令牌因此能读取全部空间。

最后一名管理员规则在服务层统一检查，平台管理员接口和空间设置接口都经过它，违反时返回 `409`。

## 7. 不包含

- 停用、删除用户，修改用户名，重置密码（本地账号密码仍在配置文件中维护）。
- 在界面上修改 `ADMIN_USERS` 或 `LOCAL_USERS`。
- 按用户或部门的部分公开、公开链接给未登录用户、公开空间的编辑权限。
