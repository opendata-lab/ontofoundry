# 元数据同步按库隔离（v0.2.1）

日期：2026-10-22。范围：`hotfix/0.2.1` 后端与测试；不修改前端、不提交。

## 已确认决定

| 编号 | 决定 | 来源与影响 |
|---|---|---|
| SI-01 | MySQL / Doris 连接代表服务，读取必须指定业务库；PostgreSQL 仍指定数据库，schema 默认 public。 | 用户已授权的连接规则；执行约束，不增加核心模型概念。 |
| SI-02 | 库名从请求到任务、源库读取、快照主键保持一致，不按表名跨库合并。 | 已有 `(connection_id, schema_name)` 足够表达；同名表属于不同来源。 |
| SI-03 | 后台执行重新检查库名及允许范围，不能让遗留空库任务落到驱动默认库；保存时检查观察结果的库名。 | 执行正确性，不新增存储或业务状态。 |
| SI-04 | 保留显式 Doris information_schema 过滤和完全限定的类型补查；不猜测或裁剪带前缀的库名。 | 现有读取路径；本机没有 Doris，多 catalog 行为需要现场验证，不能据此宣称根因。 |
| SI-05 | 使用已有迁移清空元数据快照、同步任务和批次，保留数据集定义，部署后重新同步。 | 用户已确认的迁移，不修改业务源库。 |

## 证据与验收

逐项核查列库、列表、建任务、后台读取、保存、assets 和 registered-tables，以及前端请求参数。区分可复现的缺陷和尚未证实的现场原因，不将“连接 URL 有 database”直接等同于“驱动忽略显式 schema”。

用 SQLite ATTACH 构造多个业务库（同名表字段不同、各有独有表、视图），通过真实 API 和后台任务验证 MySQL inspector 路径及 Doris information_schema 路径；另外检查 MySQL 方言发出的限定 SQL。验证省略库名、遗留配置、遗留任务、权限变更和错误观察结果不能串写。

真实验证脚本只放临时目录；从用户指定 .env 读取密码，不输出密码。使用临时 SQLite 平台库，源 MySQL 仅执行只读会话设置、列库、列表和反射，打印逐库源清单与快照清单。当前沙箱首次预检禁止连接 127.0.0.1:3306，若仍不可达须记录失败而非声明通过。
