# Entity Resolver：实例链接与消歧

日期：2026-10-21。状态：已确认，待实施。来源：用户 2026-10-21 与 ChatGPT 讨论中的“Entity Resolver：统一实体链接与消歧”及当日决定。

## 1. 目标

问题或材料中的实体提及（如“星河电子”）在给定实体类型下找到对应实例，并明确告诉调用方是唯一命中、有歧义还是没找到。Agent 不得按名称取第一个结果。

现状：`search_objects` 只搜文档事实；数据库实例搜索（REST）对主键和各字段做“包含”匹配，按主键排序，不返回匹配状态。

## 2. 决定

| 编号 | 决定 | 状态 |
|---|---|---|
| ER-01 | 新增 MCP 工具 `resolve_entity`，输入 `mention`、`object_type_id`（UUID，不接受英文标识或名称），可选 `limit`（默认 10，上限 50）。空间与版本由令牌绑定。 | 已确认 |
| ER-02 | 匹配级别：① 业务标识属性精确命中；② 标题属性精确命中；③ 标题属性包含命中。语义（向量）召回与上下文消歧本期不做。 | 已确认 |
| ER-03 | 状态：`MATCHED`（① 或 ② 唯一命中；或仅有一条 ③ 包含命中）、`AMBIGUOUS`（同一最高级别多条命中）、`NOT_FOUND`。仅一条包含命中时视为 `MATCHED`，调用方在回答中写明按哪个实例理解。 | 已确认 |
| ER-04 | 不输出数值分数；每个候选返回命中级别与命中的属性和值。分数待有标注样本校准后再考虑。 | 已确认 |
| ER-05 | 名称规范化：只做去首尾空白、Unicode NFKC、英文小写三步，用于判定精确／包含；不做去“有限公司”、简称、曾用名、拼音。 | 已确认（2026-10-21） |
| ER-06 | 数据来源：实体类型有数据库映射时查业务库（只读，经现有实例查询计划与权限）；同时查已接受的文档事实。两处结果分别标注来源，不合并、不推断同一实体。 | 已确认（2026-10-21） |
| ER-07 | 不在平台建实体索引，每次解析直接只读查询源系统（见事实仓库设计 FS-03）。 | 已确认（2026-10-21） |

## 3. 匹配过程

1. **粗筛**：业务库按映射生成只读查询，在业务标识属性和标题属性对应的列上做不区分大小写的包含匹配，最多取 `limit + 1` 条；超过时返回 `truncated: true`，建议调用方补充条件。文档事实按同样属性在事实值上匹配。
2. **判级**：对候选逐条判定命中级别（ER-02）；判级前按 ER-05 规范化。
3. **排序**：按级别，再按命中值长度、实例键排序。
4. **定状态**：按 ER-03。

没有标题属性、也没有业务标识属性的实体类型返回 `NOT_RESOLVABLE`，提示先在模型中设置标题属性或业务标识。

## 4. 输出

```json
{
  "workspace_id": "…", "version_id": "…",
  "mention": "星河电子",
  "object_type_id": "…",
  "status": "AMBIGUOUS",
  "truncated": false,
  "candidates": [
    {"source": "database", "entity_ref": "…", "display": "星河电子有限公司", "match": {"level": "name_contains", "property_id": "…", "value": "星河电子有限公司"}, "identifiers": {"supplier_code": "SUP-1001"}},
    {"source": "database", "entity_ref": "…", "display": "星河电子终端有限公司", "match": {"level": "name_contains", "property_id": "…", "value": "星河电子终端有限公司"}, "identifiers": {"supplier_code": "SUP-1002"}}
  ]
}
```

- `entity_ref` 沿用现有实例引用格式（数据库实例为类型 id + 业务键，文档事实为事实 UUID），后续查询直接使用，不再按名称匹配。
- `identifiers` 给出业务标识属性的值，便于追问时让用户区分。

## 5. 与其他能力的衔接

- `search_ontology` 返回的 `unmatched_terms` 由 query-understanding Skill 判断哪些是实体提及，再调用 `resolve_entity`。
- instance-extraction 写事实前可调用它检查是否已有同一实例，有则用已有 UUID 更新，不重复创建；仍以人工审阅为准。

## 6. 验收

- 虚构采购协同领域：同前缀多家供应商、唯一包含命中、业务编码精确命中、未找到、无标题属性的类型。
- 权限：无实例权限时拒绝；业务库只读查询经现有白名单。
- 问数 Agent 遇到 `AMBIGUOUS` 时追问而不是任选其一。

## 7. 不做

- 不对实例做向量化，不做跨来源实体合并，不输出置信度。
- 不新增别名、曾用名等模型概念；数据中已有并映射为属性的列，可在后续版本加入匹配范围。
