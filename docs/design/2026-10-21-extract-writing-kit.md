# 抽取轮固定写法包与离线证明

## 1. 范围与已确认决定

用户于 2026-10-21 确认推荐 e：固定抽取写法包、01–05 模板、统一阅读路线、写后即检。平台不按材料或业务名称选择形状。未同步表没有物理列时只提出有依据的实体、属性、关系与基于表的数据集，不猜列，不生成依赖未知列的映射、SQL 或指标；最终列未交付项并提示“先在数据管理同步该表，再发起补齐”。同步后一次小改动／增量补齐。

## 2. 实现设计

- `references/extract-kit/` 保存可整套合并的 create 裸数组，01 类型与值域、02 联系、03 来源与映射、04 指标规则、05 空事实。所有名称虚构，展示名中文。`show_example.py --part 01` 至 `--part 05` 为固定入口；`--values` 返回取值速查，`--guide` 返回简短写法说明。每次输出不超过 8 KiB，同一工具回合发出多个有界调用，不串接输出。
- 取值文件从当前提案契约枚举及联合分支常量提取；测试逐项对照契约。正例整套经片段检查、完整检查器与服务端最终候选图／证据检查，避免仅对壳做 Schema 校验。
- 取得工作包后的下一工具回合初始化并读齐带原行号材料、前轮计划、表结构。下一回合读原则与固定包，最迟 T3–4 同步修订 plan／清单／notes 并写 01。抽取不回读 methodology／core-model。协议模板独立于抽取示例。
- Schema 只给检查器；包未覆盖时定点查询已有正例；仍未覆盖只交付合法范围并说明缺项，不遍历 Schema，也不把格式问题伪装成业务选择。
- 错误路由仅使用 JSON Pointer、目标类型、操作和判别字段，覆盖 filter、COUNT、direct/data_join、query、ratio、metric expression 和字段 expression。初始化只按工作包给出的两个输出路径建父目录。
- 平台只增加固定写法包入口，不选择语义。没有核心模型概念、契约、迁移或 Ossie 例外变更。写法包和工作包入口是自创执行优化，删掉只损失抽取效率；现有模型足以表达全部语义。

## 3. 离线证明与预算

保存虚构星河零售材料、前轮确认计划、五表结构、保守 01–05 与显式补退款列后的预期 01–05。保守版本没有退款物理映射、事件 SQL 或退款指标；语义不因缺物理列被删除。测试以写法包的字段路径／判别值覆盖夹具形状，再执行 check_part、prepare_result、parse_result，另在保守候选图上实际生成增量补齐批次，复用原元素 UUID。

抽取首读必须计入工作包、全部带行号材料、前轮计划、表结构、技能入口、原则、包说明／速查／01–05，以及已知系统和动态提示；不再用“不重读材料”压低数字。总上限 36,000 B，单次输出 8 KiB，SKILL 仍 ≤4,000 B。正常目标 9–11 轮，含两次修正 13–15 轮；属于路径估计，无模型行为实测。部署、真实探测和 Agent 行为不在本轮证明范围。
