## 1. 目的与适用范围

集中记录企业 ToB 产品界面优化中逐项达成的共识，供当前产品执行、后续产品复用，并作为未来提炼设计 skill 的依据。

## 3. 执行规则与检查方式

### UI-001：没有键盘操作需求

来源：用户确认的产品取舍。

- 不专门增加表格行键盘入口、方向键导航、自定义快捷键或完整的纯键盘操作流程。
- 界面评审、外部技能审查和验收时，不因缺少上述能力产生待修复项。
- 外部设计 skill 或通用检查清单提出键盘操作建议时，按本条产品共识处理。

示例：业务对象表格支持鼠标点击行打开详情，即使没有 Enter、空格或方向键操作入口，也不因此判为缺陷。

检查方式：确认优化计划、评审结论和验收项没有把缺少键盘操作支持列为问题。

### UI-002：逐项确认并回写

来源：用户确认的协作方式。

- 可用完整线框方案一次覆盖相关页面、页签及查看/编辑状态，批量确认后连续实施，减少逐项问答。
- 不再为已确认方案中的间距、列宽等实现细节重复提问；新增业务取舍再确认。
- 新共识使用稳定编号，记录主题、决定、确认日期，并补充执行规则、具体例子和检查方式。
- 调整已有共识时，更新对应条目及当前项目中的引用，避免多份规则相互冲突。

检查方式：每项已实施的优化都能对应到已确认共识；尚未确认的建议不写成生效规则。

### UI-003：零值与无值分开显示

来源：用户确认的产品取舍。

- 已取得数据且计数为零时显示 `0`，表格计数和页签数量遵循同一规则。
- `—` 表示无值或不适用，不能替代已知的零值。
- 数据尚未取得时显示加载状态；加载失败时显示错误提示，不能把未知结果显示为已知的零值。
- 已有明确业务文案的缺失状态保留原文案，例如“未登记”。

示例：虚构的“订单明细”数据集关联 0 个对象、0 个指标时，两列均显示 `0`；未配置快照字段显示 `—`；列信息未登记显示“未登记”，已登记空列清单显示 `0`。

检查方式：分别检查非零、零值、无值、不适用、加载和加载失败；确认同一页面的表格与页签没有把已知的 `0` 隐藏或替换成 `—`。

### UI-004：优先解决专业感与布局问题

来源：用户确认的优化目标。

- 优先检查页面和弹窗的布局结构、样式一致性、间距、空间利用、信息层级、内容对齐，以及查看、编辑和页签切换的交互。
- 结合实际页面说明现状和改后效果，可将相关问题合成完整方案统一确认。
- 不把通用设计清单中的每个细节都自动列为优化任务。

示例：先检查本体详情弹窗及其各页签是否存在布局不稳、空间浪费或编辑拥挤，再讨论具体改法。

检查方式：每项优化都能说明解决了哪一处具体布局或使用问题。

### UI-005：当前阶段暂缓测试

来源：用户确认的当前协作安排；属于项目阶段偏好，跨产品复用或提炼 skill 时需单独确认。

- 当前阶段默认不运行单元测试、构建、自动化视觉测试或额外启动浏览器测试流程，优先完成已确认的功能与界面改动。
- 讨论时可读取代码、已有截图和设计文档；不为每个小改动单独组织测试。
- 暂缓验证的内容如实记录，集中验证时间后续再安排。

检查方式：交付时明确是否经过测试，不把未执行的验证写成通过。

### UI-006：多页签详情弹窗保持框架稳定

来源：用户确认的布局与交互取舍。

- 同一窗口尺寸和展开模式下，切换页签、进入或退出编辑，不因内容多少改变弹窗外框高度和位置。
- 标题、页签保留固定位置，正文使用剩余空间并独立滚动；编辑时在顶部原“编辑”按钮位置显示“取消”“保存”，不另设底部操作栏，不因进入编辑改变正文可用高度。
- 普通与展开模式分别遵循稳定的尺寸规则，并受视口约束；具体尺寸由各产品自己的设计变量管理。
- 先实现公共框架，内部页签可用一套完整方案批量确认后连续优化。

示例：从简短概览切换到较长的属性表，或在属性页进入编辑，标题和页签位置保持不变，长表格在正文内滚动。

检查方式：集中验证时比较同一窗口下各页签及查看/编辑状态的外框和页签位置，确认滚动正文时仍可操作标题、页签及顶部保存和取消。固定尺寸框架已实现，顶部按钮调整已随全量方案实施，暂未运行测试或截图验收。

### UI-007：概览兼顾信息阅读和关系图可读性

来源：用户确认的概览布局取舍。

- 基础信息与关系图并列时，采用约 40% / 60% 的空间分配；信息区不再嵌套成双列字段，使用单列“标签＋值”，长内容自然换行。
- 两侧标题对齐，标题与内容使用一致的间距；关系图增加可用高度，避免占据大块空间却把节点和文字缩得过小。
- 依据实际内容容器宽度切换布局，空间不足时上下排列，避免按整页宽度误判弹窗可用空间。

示例：虚构的“销售订单”对象可以完整显示“主数据集：销售订单每日快照”，右侧关系图中的对象名称也保持可读。

检查方式：集中验证时检查长字段换行、两侧标题与间距、节点文字大小，以及窄容器下的上下布局。本次实现暂未运行测试或截图验收。

### UI-008：概览只分基本信息与数据来源

来源：用户对原版概览布局的明确取舍。

- 左侧通过标题和分割线组织基本信息与数据来源，标签和值对齐。
- 不设置“实例标识”独立分区；标识在模型中的定义及属性表中的约束能力继续保留。

检查方式：概览不出现独立的实例标识区，既有标识功能没有因展示调整被删除。

### UI-009：复杂属性使用列表与配置区

来源：参考 Foundry 官方属性编辑器截图，经用户确认，结合本产品能力采用。

- 列表负责选择和比较，配置区负责完整阅读与编辑，不把全部表单塞进表格单元格。
- 本产品采用约 55% / 45% 的空间分配和统一顶部保存；比例是本产品的实现取舍，不宣称是 Foundry 的固定比例。
- 沿用既有业务定义、继承约束及数据绑定能力，不为复刻界面新增后台功能。

检查方式：集中验证时检查选中行、完整字段、长表达式、继承只读与窄容器布局；当前阶段暂缓测试。

### UI-010：实例来源作为筛选维度

来源：用户明确要求实例页不再通过文档事实、数据库页签切换。

- 来源使用下拉过滤器，每次只显示文档或数据库，不提供“全部来源”，不合并分页。
- 搜索、结果列表与详情保留统一的页面上下文；单来源列表不重复添加来源列，详情提供来源信息。
- 来源的筛选与展示组织不代表跨来源记录已自动合并，身份匹配和重复处理沿用已确认的数据语义。

检查方式：实例来源没有页签或分段切换器，没有“全部来源”，切换来源重置分页及详情。本条已实施，暂未运行测试。

## 4. 跨产品复用与后续 skill 提炼

- 复用本文时保留共识编号、适用范围和执行规则，项目实现细节由各产品自己的设计文档承接。
- 后续提炼 skill 时，以“适用场景 → 已确认规则 → 执行步骤 → 检查方式”组织内容，保留具体例子。
- skill 输出应遵循产品已确认决定，不能用通用设计偏好覆盖产品取舍。
- 本文先作为持续维护的设计共识来源；skill 提炼时再确定技能结构与安装方式。

### UI-011：按任务组织列表与详情

来源：用户确认关系、规则和实例页参考 Foundry 的信息组织。

- 关系、规则通过紧凑列表选择，在右侧完整阅读及编辑；关系先业务连接后绑定，规则先规则内容后补充说明。
- 实例以结果表格为主，选中后显示右侧详情，收起后恢复全宽。
- 搜索、筛选和动作对齐，避免搜索与发布同行、重复分割线及过早上下堆叠。
- 比例、断点和间距由项目设计规范管理，已有权限、继承及保存语义继续生效。

检查方式：本次按用户要求人工查看了页面，并修正工具栏错位及窄容器堆叠；未运行自动化测试。

### UI-012：单项详情不重复承担目录导航

来源：用户指出单条关系详情中再放关系列表多余。

- 区分目录、对象内关联列表和单项详情；单项详情不重复提供同类目录。
- 单条关系按任务组织基本信息、数据绑定、规则与实例；用户补充允许使用 Tab，不将无页签作为硬约束。少量强相关信息放在同页，配置和实例浏览可拆为不同任务页。
- 保留既有能力、权限、顶部统一保存及旧深链接的可达性。

检查方式：关系详情不嵌套关系列表；页签能对应独立任务，避免过度拆分。已实施关系定义 / 实例两个任务页签；暂不跑测试。

UI-012 内容收敛补充：单条关系的两端与基数就近展示，避免标题和正文重复；查看时只展示有值的补充信息，编辑保留完整字段；绑定必须明确两端归属；无规则时显示 0 和静态空说明，编辑仍可添加。以上已获用户确认并实施，未运行测试。

UI-012 最新实施：关系定义 / 实例两个页签已获确认并实现。定义页集中两端及基数、左右字段对应、补充信息、规则；实例独立浏览。单条详情不嵌入关系列表。

### UI-013：参考页面的信息组织适配当前工作空间

来源：用户要求参考 Fabric，并进一步明确只参考信息组织，相关字段应同行。

- 参考微软 Relationship configuration 的信息分组，按当前弹窗宽度组织同行字段及左右端点；不复制参考图的窄面板尺寸，关系与对象详情共用相同宽高。
- 当前页面已有的工作空间上下文不在关系来源区重复显示；配置项按模式渐进展示，例如开启映射表才展示选表及列映射。
- 原图专属平台概念不自动加入模型；对应到已有定义，差异记录到项目设计。
- 保留本产品已确认的顶部取消/保存与既有权限，不新增不可用或重复的按钮。

当前关系页已按此方向实施；模型和契约未变，暂未运行测试。

### UI-014：任务页签使用明确业务名称

来源：用户明确关系页采用概览 / 映射 / 规则，实例放概览下方。

- 概览同时回答关系连接谁与有哪些实例；实例不强制拆成独立页签。
- 映射只承担映射表配置，开启后才展示配置表单。
- 规则作为独立任务，不将业务定义、规则和管理操作统一塞进“其他设置”。
- 具体页面能力及兼容规则见当前项目设计，不改变模型与权限。

### UI-015：关系按双向语义解释

来源：用户提供 Foundry 关系编辑截图，要求参考来源对象、目标对象、基数及反向名称的信息组织。

两端对象先并排定位，正向/反向分别用自然语言数量行解释；关系名称（可选 display_name）在顶部基本信息与英文标识（必填 name）同行，关系含义及两端角色名独立维护。数量从既有基数推导，不为两个方向新增独立模型字段；只提供现有模型可表达的组合。基本信息不重复编辑同一名称与基数，实例继续放概览下方。

### UI-017：按依赖选择配置

物理来源采用数据库连接 → 库 / Schema → 表的下拉顺序，已由连接确定的数据库类型不重复选择；更换上游时清空失效的下游配置。可选功能先明确启用，再展开必填参数，例如先勾选快照表再选择快照日期字段。已有字段能表达启用状态时，不为界面另存重复的业务标志。

构建配置分组补充（2026-10-19）：文件上传/已有材料归业务知识，数据库选表归独立业务数据分区；长侧栏滚动，不压缩各分区或让上传框覆盖后续内容。

### UI-018：收起释放空间，选中状态避免重复

资源侧栏收起后释放整列空间，只保留就近展开入口，不留空白窄栏。选中项已在列表和主内容高亮时，不再增加重复名称的浮动条；详情和清除操作保留在现有直接交互中。图谱使用画布左上角展开按钮，列表使用工具栏入口，避免覆盖正文。

### UI-019：本体浏览与统一管理

本体视图直接展示语义关系，移除不能突出重点的全局分层总览及模式切换。本体对象统一管理实体、关系、指标，以三个页签组织；导入、导出、发布位于统一目录右上角。侧栏不再为关系和发布重复设项，旧发布及详情入口保留兼容。本条替代此前将导入安排在本体视图的入口决定，以及尚未交付的全局数据来源并列图示。

### UI-020：构建结果分类与任务内操作

模型分类使用带图标、名称和数量的网格选择按钮，保留零值，不让分类在窄栏横向隐藏；搜索与发布同行。会话历史和新建属于对话任务，放对话区右上角，以图标显示，历史通过弹窗选择。发布属于草稿任务，放在本体草稿页签，只在提案已形成实际草稿修改后启用，保留既有发布预检。

### UI-024：图上用弹窗，其他入口用详情页

来源：用户确认（2026-10-20）。按钮加箭头的入口样式过重，改为文字链接；弹窗只服务于在图上快速查看。
