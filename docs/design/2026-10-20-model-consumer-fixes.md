# core-1 使用方一致性修复

2026-10-20 修订：名称、旧数据读取兼容及 Ossie 扩展方式以[名称统一设计](2026-10-20-display-name-unification.md)为准；旧本体清理，不保留读取兼容；MCP 仅输出 name 与 display_name。

依据：2026-10-14 核心模型设计及 2026-10-19 关系读法的已确认决定。本次不新增核心字段、状态枚举或迁移；修复提案校验与读取投影。

## 已确认决定

| 范围 | 做法 |
| --- | --- |
| 提案引用 | 按元素类型及字段路径解析；Mapping.fields 的键是属性技术名，绑定值中的 source_id 是局部来源名。事实 values、证据、SQL 不解析为引用。结果消费边界将意外解析异常送入既有拒收/修复流程。 |
| 生成契约 | 关系 name 的 ASCII 标识和 verbalizes 的端点占位符规则写入 Pydantic 生成的 Schema；同步核心及提案 JSON Schema。没有新增模型字段。 |
| 离线检查 | 检查 Schema、操作形态、批次引用及完整固定结果头；提供草稿和元素哈希时核对 before、目标类型和哈希。完整最终图与证据真实性仍由服务端检查。 |
| 事实标题 | 提案候选上下文、发布差异复用 document_display_text；关系事实使用两端标题，不恢复持久化标题字段。 |
| 关系投影 | 使用有效关系连接、两端有效列绑定及来源连接推导 bound/unbound/cross_connection；虚拟父按具体子绑定检查，子对象使用继承关系本地绑定。自关联按两个端点分别投影方向，保持同一 id。 |
| 材料与技能 | 补充继承覆盖、标识、标题和事实最小提案示例；表材料明确来源上下文、Dataset 位置、有序 key_columns；MCP 关系外壳 technical_name 仅作读取兼容。 |

## 边界

不修改 apps/web、分发产物及他人已有修改。不 commit/push。前端无需新增字段；关系校验规则与双向关系列表消费需由前端维护者核对。运行时技能同步与重启按 DataAgent README 由部署流程执行，本次不操作远端服务。
