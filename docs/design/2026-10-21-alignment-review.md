# 对齐审阅：相似定义与业务／物理差异提示（P1）

日期：2026-10-21。状态：已确认，待实施（路线图步骤 4，用户授权按计划推进）。来源：语义锚定路线图 P1“双通道融合”、Codex 核心竞争力方案方向二“可解释的语义对齐与业务审阅”。

## 1. 问题

- 定义层面没有重复提示：Agent 新建“供货商”，而本体里已有“供应商”，审阅人看不出来；现有“可能重复”只覆盖文档实例的业务标识。
- 业务声明与物理观察的差异看不见：材料说“已提交订单必须有供应商”，提案把属性设为必填，但来源列允许为空；审阅人只能自己去查表结构。

## 2. 决定

| 编号 | 决定 | 状态 |
|---|---|---|
| AR-01 | 新增定义（实体、属性、关系、指标）的提案详情显示“可能已有的定义”：用本体检索服务（`services/ontology_search.py`）以提案的显示名、英文标识和同义词检索当前会话模型与已发布本体，取同类型、非自身的前 5 条，附命中原因（名称、同义词、描述），按检索排序展示。只读提示，不改变提案状态，不自动合并。 | 已确认 |
| AR-02 | 本期不提供“把新增改为复用已有定义”的一键操作：定义的引用改写牵涉依赖与 client_ref，审阅人拒绝后可在对话中要求 Agent 复用。 | 已确认 |
| AR-03 | 属性提案显示业务声明与物理观察的差异：属性声明必填，而其映射的来源列在已同步表结构中允许为空时，在该字段旁显示“物理差异”说明（列名、表、观察时间）。只提示，不阻止接受或发布，不推断哪一方正确。“唯一”本期不比对：已同步的表结构只有主键，没有唯一索引，无法可靠观察“不唯一”。 | 已确认（实施时收窄） |
| AR-04 | 两类提示都在读取提案详情时实时计算，不写入提案、模型或数据库（不存可推导信息）。 | 已确认 |

## 3. 接口

提案详情返回新增两个字段：

- `similar_definitions`：`[{id, kind, display_name, name, match: {by, text}}]`，仅新增定义提案有值。
- `physical_differences`：`[{path, declared, observed, column, table, schema, connection_name, observed_at}]`，本期 `declared` 为 `required`、`observed` 为 `nullable`；仅属性提案有值。

## 4. 界面

- “可能已有的定义”：提案详情中、字段差异下方一个小节，每行名称（可点进详情）、类型、命中原因。
- “物理差异”：沿用就近原则，显示在对应字段（必填、唯一）的提案值右侧，与来源问题标记同一位置和样式（提示色，不是错误色）。

## 5. 验收

- 新建“供货商”而已有“供应商”（同义词含“供货商”）时出现提示；新建与已有无关的实体时不出现。
- 必填属性映射到可空列时显示差异；列不可空或属性非必填时不显示。
- 不影响接受、发布与现有提案测试。
