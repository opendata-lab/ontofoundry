# 建模失败后在已有成果上继续（按基线保留，由 Agent 决定）

日期：2026-11-13。状态：已确认方向，待实施。来源：大型建模会话中，运行结束时提交未通过平台检查、修正轮次用完，用户重新发送后 Agent 从头建模，耗时长、成本高且没有意义（2026-11-13 用户反馈）。分析与评审见 `~/.agents/handoffs/2026-11-13-codex-modeling-cost/`、`2026-11-13-codex-resume-design-review/`（只读源码核对）。

实施见[计划](../plans/2026-11-13-modeling-resume-plan.md)。

## 1. 现状

- 每条建模消息生成新的运行令牌；DataAgent 话题跨轮复用，工作区文件保留。
- `integrations/dataagent/shared/scripts/init_workflow.py` 发现片段属于另一个运行令牌时，把 `modeling/parts/`、`modeling/checks/` 移入归档，本轮从空目录开始；`plan.md`、`notes.md`、范围文件 `entities.json`、`issues.json` 不处理，可能与新片段不一致。同一令牌重复初始化时保留片段。
- 收尾时平台检查不通过最多修正三轮（按运行令牌计）；仍不通过就不提交，会话标为 `failed_permanent`（`services/model_result.py`）。运行被取消或超时也会落到同一结果状态（`services/modeling_runs.py`）。
- 因此再发一条消息，Agent 就重新计划、读材料、抽取全部片段。
- 修正轮次用完后，平台提示“删去仍不通过的提案组后提交”，但代码在看内容之前就按轮次拒绝，这条路走不通（`services/proposal_submit.py`）。

## 2. 决定

| 编号 | 决定 | 状态 |
|---|---|---|
| MR-01 | **成果按基线保留，不按运行令牌**：上一轮的工作文件能否留给下一轮，只看它依据的内容有没有变。基线包括：会话的基版本 ID 和摘要、会话草稿摘要、材料清单摘要、表范围与结构摘要、实例基线（变化序号、修订号、摘要）。会话修订号每条消息都会增加，不作为依据；用户消息保存成的材料（`origin=conversation_request`）不计入，因为 Agent 本来就读这条消息并据此决定；其他会话发布新版本不影响本会话的基线，合并由现有三方合并处理。来源：用户提出以版本为基线（2026-11-13）；Codex 补全草稿、材料、表和实例。属于执行优化，不进入本体模型。 | 2026-11-13 用户确认 |
| MR-02 | **平台只决定“能否保留”，不决定“怎么做”**：同一会话、基线不变、平台按上一轮令牌查不到入库批次时，保留上一轮的全部工作文件；否则整体归档。不区分失败、修正用完、取消或超时，也不看新消息的内容。 | 2026-11-13 用户决定 |
| MR-03 | **由 Agent 决定怎么继续**：保留时，技能读新消息、已有片段清单、已确认的范围和上一次检查报告，自行判断：只修报错后提交、补写缺少的片段、按新要求改受影响的部分，或放弃已有成果从头开始。例如新消息是“继续”就只修报错；是“不要生成指标”就删掉指标片段再提交；只写了类型片段就按范围补写其余部分。 | 2026-11-13 用户决定 |
| MR-04 | **不依赖 Agent 运行时**：续做所需的信息全部放在工作包和工作区文件中，判断写在技能的步骤和脚本里，不新增 DataAgent 运行时功能，便于日后在 ZCode、opencode 等客户端使用同一技能。 | 2026-11-13 用户决定 |
| MR-05 | **平台确认入库**：是否已入库按上一轮令牌在平台查询，不依赖 Agent 本地记录（响应可能丢失）。已入库时即使基线没变也整体归档，避免重复提案。 | 2026-11-13 用户确认 |
| MR-06 | **修正提示改正**：轮次用完时提示改为“本轮修正已用完，结果未提交。请在回答中说明未通过的问题；用户再次发送消息时，可在本轮成果上继续”。 | 2026-11-13 用户确认 |

不做：跨会话共享成果、部分提案入库（与[串行原子建模](2026-10-26-serial-atomic-modeling.md)冲突）、DataAgent 上下文裁剪和换用便宜模型。这些等有了分阶段用量数据再定。

## 3. 机制

1. **平台判断保留**（`api/agent_conversation.py`、`services/modeling_input.py`）：每次运行计算基线摘要，存入运行清单 `run_manifest_json.baseline`。新消息替换清单前取上一轮清单比较；上一轮是建模模式、按其令牌查不到入库批次、基线相同，则在工作包 `run.resume` 写入上一轮令牌和整条未入库链上的令牌 `previous_run_tokens`（某一轮在初始化前就失败时，工作区标记仍是更早的令牌）。判断在现有会话锁和空闲门禁之内进行。
2. **初始化**（`init_workflow.py`），按顺序：
   1. 工作区标记的令牌等于本轮令牌：本轮重复初始化，保留全部文件，不做其他处理。
   2. 工作包带 `resume` 且标记的令牌在 `previous_run_tokens` 中：保留工作文件（`parts/`、`checks/`、`plan.md`、`notes.md`、`entities.json`、`issues.json`），改写标记为本轮令牌，把 `plan.md` 中的工作包改成本轮的（旧工作包的提交凭据已失效），打印续做摘要：各片段条数及类型、范围项数、最近一次内容检查的错误数和前 3 条错误（片段比报告新时提示报告可能过时），提示先读新消息再决定。`--restart` 把成果按上一轮令牌归档到新目录，不与已有归档混放。
   3. 其他情况：上述文件整体归档，本轮从空目录开始。
3. **检查报告留档**（`prepare_result.py`、`check_result.py`）：每次本地或平台内容检查都把报告另存一份到 `modeling/checks/latest-content-check.json`（含候选摘要和片段来源），修正轮次用完的拒绝和网络错误不覆盖它，单独记录。
4. **技能路由**：`ontology-discovery` 和 `entity-extraction` 两个技能入口在初始化后，若打印了续做摘要，先读新的续做步骤 `shared/references/steps/resume.md`，按 MR-03 选择：直接收尾修正、补写缺失片段、改受影响部分，或调用 `init_workflow.py --restart` 归档后从头开始。计划模式下，凡是要改片段都先提交简短计划获批，不沿用上一轮的批准。
5. **提交成功后归档**（`prepare_result.py`）：收到平台通过回执并写好结果留档后，脚本把六类工作文件全部移到 `modeling/submitted/<令牌>/`；归档失败只记日志，仍报告平台已入库。
6. **提示改正**：`services/proposal_submit.py` 按 MR-06 改写 `REPAIR_BUDGET_EXHAUSTED` 消息。

## 4. 减少工具调用

按 `apps/api/evals/acceptance/tool_stats.py` 统计 2026-11-05 星河零售两次基线：全量抽取一步 26～34 次工具调用，增量一步 10～13 次。逐条看调用记录发现的浪费与改法：

| 浪费 | 改法 |
|---|---|
| 笔记模板写“≤2 KB”，Agent 用 5 次调用逐字删到 2 KB 以下 | 去掉字节数，只要求记要点 |
| 原则、说明、取值、01–05 分 4 次读（干净环境 8 次） | `show_example.py --extract 1`、`--extract 2` 两页读完，每页低于 DataAgent 16 KB 直接显示上限 |
| 每写一两份就检查、另写 python 自检 | 写完 01–02、03–05 各检查一次；检查脚本已校验格式与引用 |
| 增量要分两次读说明和 update 正例 | `--incremental-guide` 一次带出 update 正例 |
| 用户消息被列为“新增材料”，Agent 再读一遍 | 不计入新增材料，路径旁注明不必再读 |
| 平台报错全部打印、续做时还要另读报告 | 平台报错按 2.7 KB 截断并给续读命令；续做摘要直接列前 3 条 |

技能文件仍守住 `scripts/offline_budget.py` 的字节上限。真实效果以星河零售全量与增量回归复测为准（DataAgent 环境恢复后进行）。

## 5. 验收

| 场景 | 预期 |
|---|---|
| 修正轮次用完未提交，基线不变，用户发“继续” | 保留片段；Agent 不重新读材料和抽取，只修报错后提交；新运行有新的三轮修正 |
| 同上，用户发“不要生成指标” | 保留片段；Agent 删除指标片段，按需调整依赖后提交 |
| 上一轮只写了部分片段（中途失败、取消或超时） | 保留片段；Agent 按范围补写缺失部分 |
| 草稿、材料、数据表或实例基线任一变化 | 整体归档，从头开始 |
| 其他会话发布了新版本，本会话基线未变 | 保留，不因此重新建模 |
| 上一轮已入库（含响应丢失） | 整体归档，不重复提交 |
| 同一运行内两次初始化 | 第二次保留第一次的文件 |
| 计划模式下需要改片段 | 先提交计划，获批后再改 |
| 修正轮次用完的提示 | 不再建议“删去提案组后提交” |
