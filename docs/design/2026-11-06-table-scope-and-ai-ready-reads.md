# 会话数据表范围与 AI 可读的结构化读取（2026-11-06）

状态：方向已确认（§2）；§3.3、§3.5、§3.6、§3.7 已实现，§3.4 运行时样例待实施。修订 [2026-10-20 数据集来源](2026-10-20-dataset-sources.md) DS-18 与 [2026-10-21 表结构证据](2026-10-21-table-structure-evidence.md)。方案初稿由 Gemini（argon-high）起草，Claude 核对代码后修订；评审记录在 agents 仓库 handoff `2026-11-06-gemini-table-access-design`。

## 1. 问题

1. **选表太重**：构建页“选择数据表…”是复选框列表，只能逐张勾选，没有全选、筛选和同步时间；会话最多 200 张（`api/modeling.py:450`）。
2. **表结构变成大文档**：运行开始时把所选表的全部列写成一份 JSON 表结构收据（`services/modeling_input.py:247-311`），工作包列出所有表，`init_workflow.py` 的 `table_commands` 让 Agent 读完每张表的每一列。10 张表可以接受；默认全选几百张表时，token 和上下文都撑不住。
3. **读材料也重**：`read_input.py` 把每行包成 JSON 数组（`read_input.py:12-27`），JSON 只能按 Pointer 取裸 JSON，CSV 没有结构化读取，Agent 只能逐行读。
4. **只看结构猜不准**：列注释常常缺失，`status` 是 1/0 还是字符串、哪列是粒度，要看取值才知道；平台同步只取结构，不取样例和统计（`services/metadata_sync.py:113-131`），而同步并不频繁。

## 2. 已确认的决定（2026-11-06 用户）

| T2 | 已有会话 | 未关联任何表的已有会话切换为“全部已同步数据表”；已关联表的保持所选 |

## 3. 方案

### 3.1 会话表范围

- `modeling_sessions` 新增 `table_scope`：`all`（新会话默认）或 `selected`。来源：自创的会话输入范围，属执行上下文，不进核心模型；删掉它，“全选”只能存一份几百行的静态清单，后续同步的表进不来，被移除的表会让运行失败。
- `all`：每次运行和打开弹窗时解析当前已同步、未缺失的表，`linked_tables` 为空。`selected`：`linked_tables` 存所选表，去掉 200 上限。
- 已移除或缺失的表在解析时跳过，运行照常开始，在运行记录里写“本轮略过 N 张已不可用的表”；不再像 `dataset_sources.py:183` 那样整次报错。
- 会话所选表不再阻止删除数据连接（去掉 `services/connections.py:57-60` 的 `linked_table` 引用）；删除保护只针对数据集和待审数据集提案。
- 迁移：已有会话 `linked_tables` 非空设为 `selected`，其余设为 `all`（T2）。

### 3.2 选表弹窗与左侧摘要

- 弹窗用 Ant Design `Table`，宽度同同步弹窗。列：数据表（表名，视图标注，下方一行注释）、数据源 · 库、列数、已有数据集、最近同步时间（`observed_at`，后端在 `registered_table_catalog` 返回项补上）。
- 顶部：数据源、库、类型三个筛选和搜索（表名、注释、数据集名）。表头复选框作用于当前筛选的全部匹配行（跨分页）。辅助栏显示“匹配 X 张 · 已选 Y / 共 Z 张”，操作“全选全部（切回 all）”“清空”。全选全部且无筛选时保存为 `all`，否则保存为 `selected`。
- 左侧面板不再平铺复选框：`all` 显示“全部已同步数据表（N 张）”；`selected` 少于等于 5 张列出表名，更多时显示“已选 48 / 650 张（星港ERP 30、CRM 18）”；为空显示“未关联数据表（仅从文档建模）”。

### 3.3 Agent 读表：先检索、再按需读列

实施记录（2026-11-06）：已实现，API、读取器与离线预算检查通过；完整技能套件中的本地套接字测试受沙箱限制，待 Claude 复核。未部署 DataAgent，未做真实模型验收。

- 工作包不再列出全部表、不再预先生成全量表结构收据，只放范围摘要（模式、表数、连接）。本轮固定的表结构快照作为运行文件上传到沙箱，不进上下文；修正轮使用同一快照，`t1..tN` 编号不漂移。
- `search_tables`（读取器子命令）：关键词匹配表名、表注释、列名、列注释，每页 30 张、单次不超过 4 KB，每张一行：`[ref: t12] erp.dim_supplier（表 · 星港ERP · 18 列 · PK supplier_id）供应商主数据｜匹配列 tax_no(税号)`。
- `describe_tables`：一次最多 10 张、单次不超过 8 KB，每列一行：`[ref: t12.supplier_id] supplier_id · varchar(32) · PK · 非空 · 供应商唯一编码`；宽表先列主键、外键、有注释的列，其余给续读命令。
- 技能流程：计划阶段只检索表（30 张以内直接浏览），把候选表写进计划；抽取阶段只对候选表读列。删除初始化时的全量读表批次。

### 3.4 样例与统计：运行时按需（T6）

- 新增平台 MCP 工具 `sample_table(ref, columns?)`，复用 `services/table_preview.py` 的只读预览：只查已同步表，sqlglot 构造查询，5 秒超时。返回小份文本：3–5 行样例（单元格截断约 60 字），以及在有限样本（如前 10,000 行）上算的行数、空值率、不同值数、最小/最大值、前 3 个取值。
- 权限：运行以发起人身份访问（`api/auth.py:224` 的运行级 MCP 凭据），发起人有实例读取权限（`require_instances`）才返回样例和取值；没有则只说明“无权查看样例”。不新增开关。
- 前提：建模运行目前只在工作空间已有发布版本时才拿到 MCP 配置（`api/agent_conversation.py:486`），需改为每次运行都提供。
- 样例只作理解列含义的提示，不作证据：数据会变，修正轮不可复现。证据仍引用表结构。

### 3.5 材料读取器（JSON、CSV、文本）

实施记录（2026-11-06）：已实现，API、读取器与离线预算检查通过；完整技能套件中的本地套接字测试受沙箱限制，待 Claude 复核。未部署 DataAgent，未做真实模型验收。

参照 Claude Code Read（T4），`read_input.py` 改为：

- 文本：`行号→内容` 纯文本输出，不再包 JSON；单次上限约 8 KB，末尾给下一页命令和未读范围；超长行截断并注明。
- JSON：先大纲（顶层键、数组长度、同构数组的字段与类型、一条示例），再按路径（支持数组区间）或关键词取局部；每项带 `[ref: m1#/entities/0 · L8–32]`。
- CSV：先概览（行数、每列推断类型、非空数、不同值数、示例值，前 3 行），再按行列切片或条件过滤；每行带 `[ref: m2#row:15 · L16]`，正确处理单元格内换行。超大文件统计限定扫描行数并注明。
- 不提供 jq（T5）。

### 3.6 证据

实施记录（2026-11-06）：已实现，API、读取器与离线预算检查通过；完整技能套件中的本地套接字测试受沙箱限制，待 Claude 复核。未部署 DataAgent，未做真实模型验收。

- Agent 在证据里写读取器打印的引用（`t12.supplier_id`、`m1#/entities/0`、`m2#row:15`）和原文片段。
- 表：提交时平台只为本批实际用到的表（数据集所用表加证据引用的表）生成一份小的可读表结构收据（材料，`origin=table_receipt`），把引用换成收据的行号，结构名写入 `EvidenceLocator.heading`（`domain/core.py:95`）。之后照常走现有的行范围加原文子串校验（`domain/evidence.py:42-47`），证据弹窗不用改。
- 材料：读取器打印的原文件行号可直接抄写；路径或行列写入 `heading`。
- 核心模型不新增证据类型。

## 4. 不做

- 同步时预存样例和统计（T6 改为运行时按需）。
- 核心模型新增表证据、JSON 证据或 CSV 证据类型。
- 服务端记录“Agent 读过哪些表”的状态；提交时从提案反推。
- jq。

## 5. 风险

- 关键词检索漏掉无注释的缩写表名：检索同时匹配列名和已有数据集名，并支持按库分页浏览。
- 运行时取样给业务库加压：只查已同步表、5 秒超时、有限样本，每次运行限定调用次数。
- 样例是真实业务数据：按发起人实例读取权限放行，与界面查看样例同一权限。

## 6. 删掉会失去什么

- 不做范围模式：默认全选只能存静态清单，新表进不来，删连接被卡。
- 不做检索和按需读列：全选后 token 随表数线性增长。
- 不做按需样例：只靠注释猜列含义，枚举和粒度判断容易错。
- 不改读取器：JSON 和 CSV 材料只能逐行读，浪费 token。
