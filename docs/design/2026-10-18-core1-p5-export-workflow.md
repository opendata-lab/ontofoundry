# core-1 P5：导出、交付校验与往返

依据主设计第 6、7、14.6 节及原计划 P5。核心模型和业务边界不变；适配器负责格式翻译，服务负责授权与不可变文件交付。

## 行为与边界

用户明确选择已发布版本和原生/Ossie 格式，先读转换报告再下载同一 SHA 文件。导出不修改版本、草稿或模型。原生四字段单文件保留定义与 UUID，但不包含材料内容，不作为完整备份承诺。

Ossie 按核心定义输出对象、七值类型、有效标识、单父、成员分支、规则和显示扩展；每个 Dataset 和 Metric 恰好输出一项。核心的物理来源键与业务标识分别处理；多来源及关系绑定按实际可表达程度输出，不为了通过校验改业务定义。COUNT 行数使用带登记列的精确 CASE 规范式，表达式只改已解析引用和 COUNT(*) 子节点，保留字面量、NULL 和其他算法。无法表达必需指标、空 ontology 或官方校验失败时整份无下载。

时间、物理元数据、实例、证据和规则元数据的损失按主设计规定粒度报告。平台扩展块只含批准的显示字段，不藏核心模型或材料。已有 RT 编号继续使用，不重用停用编号。

## 交付接口

`GET /api/v1/modeling/workspaces/{workspace_id}/exports/{adapter_id}?version_id=...` 返回 report、content_sha256、filename、media_type、download_url。产物在工作空间/版本/适配器内按内容 SHA 保存，下载再次校验空间、版本及完整映射/实例权限，并核对文件 SHA。缓存属于应用文件交付，不新增核心业务字段或数据库表；GET 不写本体版本。

Pydantic、JSON Schema 与前端类型同步。错误报告可读，但无效产物没有 download_url；用户可以明确切换原生格式后重新预览，不能自动切换并标成功。

## 界面与验证

沿用 U4/U6 详情弹窗、Ant Design Form/Select/Alert/Button 和 P4 报告表格。发布页与历史版本提供统一导出入口，明确版本，关闭或改格式后清理旧下载状态，防止过期响应覆盖新选择。复用已有视觉变量，不新增 CSS。

全部编辑完成后集中执行后端/前端/契约/视觉检查；13 份原生往返，01–08/10–12 Ossie 官方校验，09/13 明确失败且无产物；A/B 定向差异及可执行指标复算。局域网 HTTP 验证下载、文件名、哈希和弹窗，记录包体变化。仅使用一次性测试环境，不部署开发/生产数据库或 DataAgent。
