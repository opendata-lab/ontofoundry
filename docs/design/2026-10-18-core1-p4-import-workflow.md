# core-1 P4：文件导入审阅闭环

依据：`2026-10-14-core-model-and-format-adapters.md` 的已确认决定和对应计划 P4。P3 适配器的机械转换结果保持不变。本阶段不增加核心业务概念；导入记录是应用审计与并发控制数据，提案沿用既有审阅协议。

## 1. 行为

上传原生 core-1 或 Ossie JSON 后，保存原始文件、格式化材料、不可变转换报告与转换产物。预览只计算新增和更新，不改变会话、已发布版本，也不生成删除。原生先锁定全部 UUID+种类，再对未锁定项按技术键匹配；外部按技术键匹配。事实和证据仅按 UUID。引用使用类型位置及表达式解析结果重建，不能替换字符串字面量。

确认时核对预览哈希、已发布基线和权限，在同一事务创建独立会话与待审批次。会话草稿仍是基线；接受提案后再使用正常发布流程。重复确认返回相同会话。身份冲突、名称冲突和反向依赖阻断单独报告，可独立成立的内容仍能生成提案。报告原 target ids 不改，匹配 id 表单独保存。

## 2. 持久化与接口

`ontology_imports` 保存 workspace/user、适配器、文件名、原始 artifact/SHA、格式化材料/SHA、报告、核心产物、预览匹配结果和摘要、基线版本/SHA、确认请求哈希及会话/批次。原始文件按工作空间和 SHA 存储，不执行上传内容。原始 SHA、格式化 SHA、报告内容 SHA、预览内容 SHA 各有用途，确认验证整个预览内容及保存产物。

接口前缀 `/api/v1/modeling/workspaces/{workspace_id}/imports/{adapter_id}`：POST 原始文件预览（文件名 query）；POST `/{import_id}/confirm` 确认；GET `/{import_id}` 重开报告；POST `/{import_id}/completions` 提交人工修订。报告及材料只对当前空间成员开放，完整模型导入要求实例与映射读取授权。`ossie` 仅是 `ossie-0.2` 地址别名。

## 3. 待补全

历史转换报告始终不可变。当前状态从会话草稿、未决提案和人工修订重新计算。裸 COUNT(*) 只在用户明确选择数据集后形成新指标提案，绝不自行选择统计范围。其他转换失败项允许用户修正该条来源定义后重新转换、校验并生成新提案；数据集元数据通过已有编辑流程修订。每次修订绑定会话 revision 和草稿 SHA，保留独立批次及原报告来源，不伪造 Agent 运行。

## 4. 界面

构建页增加“导入文件”。弹窗三步：选择文件及格式、预览报告、确认待审提案。显示新增/更新/不变/阻断摘要，报告按结果筛选并展开原文与材料行号。文件错误禁止确认，条目错误保留合法提案。取消、新文件、格式变更清理旧预览；确认后选择新会话并进入提案页。会话和批次显示导入来源，可以重开报告、处理待补全。

切换工作空间时清理所选文件和旧预览；切换导入来源或会话、关闭重开报告时重置报告和补全状态，忽略旧请求的迟到响应，不显示上一会话的内容。

全部使用现有布局与 Ant Design；视觉变量沿 tokens，不新增 CSS。局域网 HTTP 验证上传及 ID 生成。

## 5. 验证

覆盖 UUID 锁定、技术键匹配、引用重写、原子改名、冲突依赖闭包、无删除、证据 SHA/行号与作者、确认幂等及过期预览、权限隔离、修订并发。13 份原生示例沿预览、确认、接受、发布；Ossie 示例保留机械结果和缺失项。执行后端与前端完整检查，PostgreSQL 实际 Alembic 升级，1440×900 截图及局域网验收。外部数据库迁移、DataAgent 部署不在本阶段执行。
