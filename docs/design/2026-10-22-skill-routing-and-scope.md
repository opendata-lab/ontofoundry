# 建模技能：入口路由、范围确认与本轮路径

日期：2026-10-22。状态：已确认并实施（main 三技能版；v0.2.x 单技能版不改）。

## 问题

- 现场建模时，Agent 在计划阶段反复推敲概念，迟迟不出清单。原计划轮要求在用户确认前就定标识、对应表、关系，并逐行映射材料，还没有轮数上限。
- 计划轮没讲清概念与实例：具名事物（如某个产品、某台服务器）可能被当成类型或拿来逐个确认。
- 三技能版存在绕过确认的路径：entity-extraction 可在缺概念时直接提出定义与实例提案；建模 Agent 提示词也没有要求先确认。
- 技能入口约 4 KB，每轮都读全部步骤细节；真实运行中 33 次工具报错里约 24 次是路径与参数问题（/tmp 或绝对路径被沙箱拦截、读错参考目录、片段未写就检查、脚本参数记混）。

## 决定

| 编号 | 决定 | 状态 |
|---|---|---|
| SR-01 | 计划轮只定范围：只列概念（名称、英文标识、说明、依据、材料中的例子），不定标识、表、关系、属性；第 3 轮前写完，拿不准写成待确认问题。 | 已确认 |
| SR-02 | 概念是一类东西，具名的具体事物是其实例：记入 entities.json 的 examples（附 example_count），不另立类型、不逐个确认，确认概念后在抽取轮作为实例提出。 | 已确认 |
| SR-03 | 有新概念必须先确认范围，确认前不写任何提案；适用于 ontology-discovery、entity-extraction 和建模 Agent 系统提示词。只新增实例或不扩大范围的小改动不确认。 | 已确认 |
| SR-04 | 三个技能的 SKILL.md 只做路由（≤1100 字节），细节拆到 references/steps/（plan、extract、incremental、facts、ground、answer，共用 finish）；每轮只读当前步骤。原 methodology.md 并入计划步骤。 | 已确认 |
| SR-05 | init_workflow.py 打印本轮路径与可复制命令，建 modeling/tmp/；prepare_result.py 支持 --work-pack、片段简称和默认 modeling/parts/；参数错误时打印本轮正确写法，文件缺失时列出已有文件。 | 已确认 |
| SR-06 | 离线预算：技能入口上限 1100 字节，计划路线 16500 字节（原 18500），步骤文件各设上限。 | 已确认 |
