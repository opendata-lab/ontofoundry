# 关系标识、角色名与读法分离

2026-10-20 修订：名称、旧数据读取兼容及 Ossie 扩展方式以[名称统一设计](2026-10-20-display-name-unification.md)为准；旧本体清理，不保留读取兼容；MCP 仅输出 name 与 display_name。

状态：已确认并实施，暂未运行测试。2026-10-19 用户确认以 Ossie 为准，保留标识 name、两端角色名称及完整 verbalizes，分别展示正向/反向关系含义。旧数据切换方案见最终决定。

## 已明确的方向

- 关系必须保留 name，含义为 Ossie relationship.name：所属对象内的关系标识，如 reports_to。
- 现有 technical_name 就是该标识职责，最终归并到 name，不重复保存两个标识字段。
- 删除的是现有 name 所承担的中文正向读法职责及独立 inverse_name 字段；完整正反读法进入 verbalizes。不影响对象、属性、规则等元素的 name。
- source_role_name / target_role_name 表达两端角色。来源下属、目标主管，正向看主管、反向看下属。
- 展示标题及计数句可以从角色名、对象类型、基数推导，不存为额外展示字段。

## 已确认：verbalizes

以 Ossie 为准保留完整读法列表，不再截取两个占位符之间的动词。角色与基数说明“每个员工有一个主管”，verbalizes 独立表达“员工汇报给主管”等完整业务含义。页面在原正反向区域分别展示、编辑完整的正向关系含义及反向关系含义，不把角色名当作关系读法。

关系标识 name、两端角色名与完整读法是三层独立信息；只有角色数量句可以生成展示，不以生成数量句替代明确提供的读法。name 的旧中文显示值不直接当成新标识；旧标识取原 technical_name。

## 影响梳理

1. LinkType 校验和前端/后端所有通用元素接口当前假定 name 存在，需改成类型感知的显示名称推导；不能只删除两个输入。
2. 契约、合并/预检、搜索、图标签、实例告警、提案和冲突展示、导入匹配及生成类型必须同步。
3. 现有版本、会话、提案 JSON 包含 name/inverse_name。需制定旧数据读取/迁移及哈希兼容方案，避免删除字段后已有空间无法打开；角色名不能从旧名称可靠回填。
4. Ossie 导入停止从读法截取中间动词，导出按已选策略输出完整读法或生成最小角色描述；RT-20 与显示扩展同步修订。
5. 现有业务例子“签约方”混作读法，需按角色与关系标识分层，不能将原角色词机械解释为动词。
6. 更新概念文档、生成 schema/type、DataAgent 技能及部署内容；不改变数据源只读原则。

已按最终决定补齐读取兼容、契约与界面。按用户要求，暂不运行测试、构建或 lint。

## 最终已确认决定及实施边界

2026-10-19 用户确认模型与线框示例，进入实施。关系 name 是唯一技术标识，原 technical_name 不再作为存储字段；保留可选两端角色名、description、synonyms、tags、data_join、evidence。删除中文名称 name 的原职责以及 inverse_name，新增 verbalizes: string[]，保留完整正反句式及额外读法，顺序有意义，不截取动词。

核心读法使用稳定端点占位符 {source}/{target}，来自既有二元端点而非新增业务概念；导入时将 Ossie 的概念/角色占位符机械转换为对应端点，导出时反向转换，不改正文和读法顺序。对象或角色改名不破坏读法引用。界面编辑使用中文占位符 {来源}/{目标} 并提供按当前对象/角色渲染的预览；一行一条读法，分别维护正向/反向组，额外同向读法保留。允许列表为空，由显示和导出生成最小角色描述，不将生成值写回核心模型。

旧 core-1 JSON 在读取时兼容：原 technical_name 迁入 name；原中文 name 与 inverse_name 分别转为 {source}原名称{target} 和 {target}原反向名{source} 的完整模板，不推断角色名，不覆写已有 verbalizes。保留旧物理快照及存储哈希，不重写不可变发布版本。新增读取兼容与旧原生文件规范化，所有后续写入只输出新结构。Python 内部只读 technical_name 属性临时转发到 name，用于既有路径引用算法，不属于模型字段或接口契约。旧哈希验证仅接受原始旧快照的规范化结果，新增写入和元素预检使用当前模型哈希。无需表结构变更，不新增 Alembic 迁移。

正向/反向读法由第一个端点占位符确定，校验每条包含两端且无未知占位符；不增加单独的 forward/inverse 持久化字段。单条字符串最长 4000 字符、最多 50 条，分别沿用现有规则表达式与标签数量上限，不新增业务限制概念。

Ossie 空读法的最小关联句由 generated_link_readings 交换扩展记录路径，仅用于往返恢复未填写状态，不进入核心模型；外部工具修改生成句后按明确读法导入。用户编辑正反分组后，按正向组、反向组排列，组内读法顺序保留；未编辑的导入/导出保持原列表顺序。

后续位置修订（2026-10-19，当前生效）：查看状态的关系标识仅在弹窗标题显示，正文不重复列出；编辑时保留“关系标识”输入。基本信息无描述、同义词和标签时整段隐藏。“对象关联”标题统一改为“关系详情”。关系实例将固定的“来源：文档”从工具栏移入表格“来源”列，每条显示“文档”；对象实例仍使用来源下拉单选，不重复加列。
