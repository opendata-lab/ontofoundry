# v0.4.0

日期：2026-11-17。基于 v0.3.2 之后的主干（#78–#96）：接口重组、统一的写入管线、实例与定义同一生命周期、技能变薄，以及接受时求值规则。设计见 `docs/design/2026-11-16-agent-platform-interface.md`、`docs/design/2026-11-15-accept-completeness.md`。

## 行为变化（升级前请读）

- **接受的实例发布后才对外可见。** 文档实例、关系实例的新增、修改、删除，接受后都先留在本会话，发布时一起生效；其他会话和问数在发布前看到的仍是发布内容。同一个实例在一个会话里有待发布修改时，另一会话不能再接受对它的修改（`INSTANCE_PENDING_ELSEWHERE`）。
- **保存不发布。** 人工在界面上的修改记为本会话已接受的人工提案，和智能体的提案一起在发布时生效；发布按钮旁显示待发布的修改数。
- **MCP 地址改了，没有转发：** 跨空间 `/api/v1/mcp`，可访问空间目录 `/api/v1/mcp/workspaces`，单空间 `/api/v1/workspaces/<空间>/mcp`。原 `/api/v1/ontology/…` 地址全部取消。外部客户端（含 `plugins/ontofoundry/`）需改配置。
- **“必填”只在属性上设置。** 只说某个属性不能为空的规则（如 `发货单.发货数量 IS NOT NULL`）提交或保存时会被退回。
- **建模技能不再在本地检查片段**，合并后直接提交平台检查，平台一次列出全部问题；每次运行最多 10 次提交。

## 新功能

- **规则在接受时求值（AC-07）。** 接受文档实例时，值类型约束和只引用本对象属性的约束会被检查，不满足就拒绝，并指明属性、值和规则；跨对象的规则或暂不支持的写法提示“规则未检查”，不阻止。
- **“全部接受”接受能通过的，** 没通过的留在待审并给出原因（如“盘亏数量（loss_qty）未绑定”），提示里逐条列出。
- **撤销与退回待审跨批次级联：** 撤销一条已接受的提案，会一并撤销在它之上的修改；“退回待审”把它和依赖它的提案放回待审。发布后，之前决定过的批次只读。
- **建模可在有待审提案时继续：** 新一轮运行能看到并修订待审提案（含文档实例），结果与待审合并为一个批次。
- **修改记录：** 元素详情里可看提案和草稿的每次变化，谁、何时、因为什么。
- **合并冲突里自己填的值** 按人工修改处理，先检查再记为已接受的人工提案。
- **建模页：** 计划与结果面板可拖动调整宽度，计划面板的打开、复制和滚动修复。

## 升级顺序

1. **确认没有进行中的建模**，备份平台数据库和文件卷。
2. 使用 v0.4.0 离线包的 `compose.yaml` 与镜像升级并启动。`.env` 不变。本版有**四个数据库迁移**，启动时自动执行：`20261116_000001`（人工保存）、`20261116_000002`（修改记录）、`20261117_000001`（发布边界）、`20261117_000002`（实例待发布修改）。迁移只新增表和列，不改已有数据：已发布的实例保持可见，已暂存的实例继续等待原会话发布。
3. **整目录替换两个建模技能**（ontology-discovery、entity-extraction）和问数技能 semantic-grounding，然后重启 DataAgent。旧目录里删掉的脚本和示例不会被覆盖安装清除，所以要先删目录再装。细节见 `integrations/dataagent/迁移说明.md`。
4. **在 DataAgent 管理后台重新登记问数 Agent 的 OntoFoundry MCP 地址**为 `<平台地址>/api/v1/workspaces/<空间>/mcp`，并发布。两个 Agent 的提示词与轮数上限不变（建模 80，问数 40）。
5. 回退：换回 v0.3.2 镜像、编排文件和技能包，并**还原第 1 步的数据库备份**（新迁移有降级脚本，但回退后 v0.3.2 不认识待发布修改，未发布的实例改动会丢失）。
