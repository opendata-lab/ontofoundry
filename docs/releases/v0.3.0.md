# v0.3.0

日期：2026-11-16。基于 v0.2.9 之后的主干（#71–#77），是接口与写入管线大改动（#78 起）之前的最后一个版本。

## 接受时检查（行为变化）

提案可以不完整，接受时必须完整（设计 `docs/design/2026-11-15-accept-completeness.md`）：

- 文档实例缺必填或标识属性、值与属性类型不符（整数不能写成文本 `"42"`、日期时间须带时间），接受时拒绝，并指明实例与属性。
- 已绑定表的对象，接受后须有逻辑键、每个属性都有绑定、来源表已同步列；只有文档实例的对象不受影响。
- 约束规则和成员条件必须是条件（结果为真或假）。
- 关系实例遵守声明的基数（多对一的订单不能连两个客户）。
- 提案面板：不能直接接受的提案标“待补全”，悬停列出原因，“待补全 N”页签单独列出；在建模会话里请智能体补全即可。
- 校验报告对未检查的实例显示“未检查”，不再显示“通过”。

**注意：** 原先能直接接受的内容现在可能被拦下，例如没有逻辑键的 Ossie 导入文件需先补齐键和绑定。这些规则尚未用真实 DeepSeek 建模复测。

## 其他改进

- 个人中心与管理页：左侧菜单、右侧内容。
- 待审提案按对象分组，属性收在对象下，可按类别筛选。
- 性能：200 条提案时接受一条不再变慢；含大量新文档实例的批次读取 400×400 从 15.8 秒降到 0.01 秒，文档实例列表、决定时的冗余读取同步优化。

## 升级顺序

1. 停止建模运行，备份平台数据库和文件卷。
2. 升级平台镜像。本版**没有数据库迁移**，配置不变。
3. 技能和两个 Agent 的配置不变，无需重装。
4. 回退：换回 v0.2.9 镜像即可（无迁移）。
