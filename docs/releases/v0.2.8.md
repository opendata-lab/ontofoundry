# v0.2.8

日期：2026-11-10。基于 v0.2.7 之后的主干（#37–#45），平台和 DataAgent 技能成套发布，与 v0.2.7 技能不兼容。

## 修复与变化

- 会话表范围：新建模会话默认使用“全部已同步数据表”，不设数量上限；运行开始时按当前已同步的表解析，后来同步的表自动纳入，已不可用的表跳过并记入运行记录，不再整次失败。会话选择的表不再阻止删除数据连接。
- 选表弹窗：表格展示数据表、数据源与库、列数、已有数据集、最近同步时间；按数据源、库、类型筛选和搜索；表头复选框作用于当前筛选的全部匹配行（跨分页）。左侧面板改为摘要。
- 建模读取更省：工作包只带表范围摘要；技能用 `read_input.py` 先按业务词检索表（任一词命中、按命中数排序），再只对候选表读列；文本带行号分页，JSON 先看大纲再按路径或条件读，CSV 先看概览再按行列读。超过 30 张表时不带关键词的检索会被拒绝并提示做法。
- 表证据：Agent 引用 `t12.列名`，提交时平台只为本批实际用到的表生成一份表结构收据，并转成普通材料证据；新增或修改的数据集用了范围外的表时报 `TABLE_NOT_IN_SESSION_SCOPE`。
- 数据表的行不再抽成文档实例；CSV 等成批记录是否抽成实例，在计划阶段询问用户（一次提交最多 500 个实例）。
- 只读 SQL 支持 `DATEDIFF`、`TIMESTAMPDIFF`；未支持的读构造报 `SQL_UNSUPPORTED`，只有写入和结构变更才报 `SQL_NOT_READ_ONLY`。
- 技能提交平台失败时输出网络原因（如 Connection refused、超时）和目标地址，并提示检查沙箱网络与 `ONTOFOUNDRY_PUBLIC_BASE_URL`。
- 调用 DataAgent 的请求头改为 `X-DataAgent-*`，修复开启认证的 DataAgent 返回 401 的问题。
- 在本地 Doris 40 张虚构表加 JSON／CSV 材料上做了三次真实建模：工具输出从 120 KB 降到 88 KB，不再整库打印表结构，最后一次 121 条提案全部通过、证据拒收为 0。
- API、前端及插件版本统一为 0.2.8。

## 升级顺序

1. 停止建模运行，备份平台数据库、文件卷、技能目录和两个 Agent 的配置。
2. 升级平台镜像，执行数据库迁移 `20261106_000001`（会话表范围：已关联表的会话保持所选，其余会话改为“全部已同步数据表”）。
3. DataAgent 需为独立版 main `c9692e0` 或更新：请求头为 `X-DataAgent-*`（OpenDataWorks 内置的旧版 DataAgent 不再兼容），沙箱网络改用 `DATAAGENT_SANDBOX_NETWORK_ENABLED=true`（旧变量 `DATAAGENT_SANDBOX_NETWORK` 会被忽略）。
4. 平台设置 `ONTOFOUNDRY_PUBLIC_BASE_URL` 为沙箱可达地址（如 `http://<内网IP>:8080`），技能才能把结果提交回平台。
5. 完整替换三个技能目录并重启 DataAgent；两个 Agent 的提示词与 max_turns 不变。用新会话验收。
6. 回退时成套恢复数据库备份、平台镜像、技能和 Agent 配置，不要只降级其中一项。
