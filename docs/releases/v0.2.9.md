# v0.2.9

日期：2026-11-15。基于 v0.2.8 之后的主干（#50–#70），平台和 DataAgent 技能成套发布。

## 新功能

- 平台登录：默认启用登录，支持本地账号和一个外部单点登录（钩子与 DataAgent 同契约）；未登录访问跳转登录页，右上角可退出。
- 用户管理：平台管理员管理用户；工作空间新增只读成员角色和公开空间。个人中心查看个人信息、管理个人令牌。
- 外部智能体网关：个人令牌访问跨工作空间的本体检索（工作空间目录、跨空间语义查询），调用异步记录；用户反馈和平台管理员的用户审计页面。附带 OntoFoundry 客户端插件（`plugins/ontofoundry/`）。
- 侧栏顶部切换工作空间；建模页使用新的输入框，可选权限模式。
- 建模失败后续做：基线未变时保留上一轮成果，Agent 按用户这条消息决定修正后提交、补写或从头开始。

## 建模更快、更省

- 表多时不再逐列手写：Agent 在 `modeling/entities.json` 每个实体、每条关系写一行，`expand_tables.py` 生成属性、值类型及取值约束、表数据集、单表映射和关系。初始化每表一行列出本轮的表、主键、外键或同名键候选、取值候选。
- 表数据集提案可不带列，平台按本轮表结构补齐；带了列也以同步的表结构为准。
- 本地检查在提交前发现未知列、查询数据集写了表位置、平台不支持的函数（函数清单由打包脚本从平台代码生成），不占修正轮次。
- 材料证据可只写行号，合并时由脚本补原文。
- 计划时先判断每张表一行代表什么；每个指标和业务规则引用材料依据（缺证据时检查给提示，不阻止提交），写完用材料里的具体数据自检。
- 问数技能包不再带建模脚本和参考文件。
- 实测（青禾生鲜 34 表、DeepSeek，同一材料从空库建模）：v0.2.8 为 38 轮、314 秒、1 次提交；本版 32 轮、246 秒、432 条提案一次通过、0 次修正，约 ¥0.24。指标口径的语义仍需人工审阅：该次实测中复购率跨统计期计数不对，拒收、闭店两条规则没有完整表达材料约束，指标和规则未引用材料行（随后 #70 要求引用并在检查中提示，尚未复测）。

## 升级顺序

1. 停止建模运行，备份平台数据库、文件卷、技能目录和两个 Agent 的配置。
2. 升级平台镜像，执行数据库迁移 `20261112_000001`（用户管理）和 `20261113_000001`（本体网关）。
3. 登录：默认账号 `admin` / `admin123`。部署前复制 `deploy/docker/ontofoundry/ontofoundry_config_docker.py.example` 为同目录的 `ontofoundry_config_docker.py` 并修改密码；需要单点登录时在其中配置 `OAUTH_PROVIDERS`、`OAUTH_USER_INFO`。生产环境设置 `ONTOFOUNDRY_ENVIRONMENT=production`、至少 32 字符的随机 `ONTOFOUNDRY_SESSION_SECRET`、`ONTOFOUNDRY_COOKIE_SECURE=true`，并使用 HTTPS 入口。原有 `ONTOFOUNDRY_OAUTH_*` 设置需移入覆盖文件，认证名称与用户 `sub` 保持原值以保留成员身份。
4. 完整替换三个技能目录（先删旧目录再安装，旧版文件不会被覆盖安装清除）并重启 DataAgent；两个 Agent 的提示词与 max_turns 不变。用新会话验收。
5. 回退时成套恢复数据库备份、平台镜像、技能和 Agent 配置，不要只降级其中一项。
