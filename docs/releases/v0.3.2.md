# v0.3.2

日期：2026-11-16。基于 v0.3.1 的补丁版本，修复 Apache Doris 元数据同步未识别 `UNIQUE KEY` / `AGGREGATE KEY` 主键的问题。

## 修复

- 修复 `apps/api/src/ontofoundry_api/services/metadata_catalog.py` 中 Doris 元数据同步函数 `read_doris_table` 仅匹配 `COLUMN_KEY = 'PRI'` 的问题（#84）：
  - Doris 在默认配置下会在 `information_schema.columns.COLUMN_KEY` 返回表模型简写（`UNI` / `AGG` / `DUP`），而不是 MySQL 的 `PRI`。
  - 修改为优先识别 `'PRI'`（兼容 MySQL 兼容索引元数据开关开启场景，避免把二级 `UNI` 索引混入主键）；无 `'PRI'` 时将 `'UNI'`（`UNIQUE KEY`）与 `'AGG'`（`AGGREGATE KEY`）按 `ORDINAL_POSITION` 顺序识别为主键，排除仅作排序前缀、允许重复行的 `'DUP'`（`DUPLICATE KEY`）。
  - MySQL 与 PostgreSQL 连接仍走各自独立反射逻辑，不受影响。
- 同步更新 `docs/design/2026-10-21-data-tables-page.md` 中的 DT-06。

## 升级顺序

1. 停止建模运行，备份平台数据库。
2. 如从 v0.3.0（或更早离线包）直接跨级升级，先按 v0.3.1 说明备份旧 `of-backend` 容器内的 `/opt/ontofoundry-api/.data/files`，待新版启动后再拷入 `/var/lib/ontofoundry/files/` 并重启 `of-backend`；从 v0.3.1 升级可跳过此步。
3. 使用 v0.3.2 离线包的 `compose.yaml` 与镜像升级并启动。本版**没有数据库迁移**，`.env` 配置不变。
4. **重新同步此前已同步的 Doris 表**：旧快照中保存的 `primary_key` 仍为空数组，升级后请在「数据管理 → 数据表」对相关 Doris 业务库重新新建全量或选表同步任务（不要只点击重试旧任务），新快照写入主键后，再发起建模即可由 `expand_tables.py` 自动展开主键属性与映射。
5. 技能和两个 Agent 的配置不变，无需重装。
6. 回退：换回 v0.3.1 镜像与编排文件即可（无迁移）。
