# 计划：数据表页左侧操作区与步骤式同步

依据：[设计](../design/2026-10-21-data-tables-page.md)。

1. 核对现有接口能否给出每张表最近同步时间、每个库的已登记表数与最近同步时间；缺什么在现有响应中补派生字段（Pydantic、JSON Schema、前端类型同步），并补后端测试。
2. 视觉一致性文档第 4 节补“左侧操作区＋右侧列表”“步骤式弹窗”两种布局模式（如尚未覆盖）。
3. 前端重构数据表页：左侧操作区（连接、库列表、搜索、排序），右侧已登记表表格，页头“同步数据表”按钮。
4. 同步弹窗四步：连接 → 库（多选）→ 表（按库分组，全选／部分）→ 进度与结果（每库一个任务，可重试），关闭后刷新。
5. 单元测试：库切换与“全部库”、搜索、排序、多库全选与部分选择生成的任务请求、进度与失败重试、关闭后刷新。
6. 视觉用例与基准：数据表页、同步弹窗各步骤；在原生 arm64 环境刷新基准（见记忆说明），1440×900 局域网截图核对。
7. 全部编辑后统一验证：后端 pytest、ruff、前端 tsc（`-p tsconfig.app.json`）、vitest、eslint、Playwright。

## 实施结果（2026-10-21）

1. 已核对：表级 observed_at 已在快照与 assets 响应中，无需新增后端字段；前端补既有字段类型。库表数由逐库快照清单计算，库时间使用快照 observed_at。schemas 接口增加 PostgreSQL 配置白名单与 MySQL database 过滤，补快照时间与库过滤测试，无契约响应形状变化或迁移。
2. 已补第 4 节布局规则，新增 DataTablesLayout，尺寸集中到 tokens.css。
3. 已实现左侧连接、库列表（全部库）、搜索排序与右侧已登记表格，超过 20 行分页；页头按钮打开同步弹窗。
4. 已实现四步弹窗、多库独立任务、全量/部分请求、轮询、批次及表结果、失败重试、返回修改及关闭刷新。提案去同步和 DatasetPicker 复用同一弹窗。
5. 已补 vitest 用例：跨库浏览、库切换、搜索排序、全量/部分请求、返回保留、进度重试、创建失败重试、关闭刷新、提案预选、重新打开活动任务。
6. 已补页面及四步弹窗视觉用例，并在原生 arm64 环境生成基准（数据表页、连接／库／表／结果四步）。
7. 统一验证进行中，最终结果记录到任务报告。

验证补充：首次默认并发 vitest 因机器负载大量触发 5 秒超时，终止后改用原生 arm64、2 worker、单例 30 秒超时重新执行；本任务定向测试首轮 7/8 通过，首次加载等待因负载超时，已延长该异步断言等待，待最终复验。类型检查与 eslint 已返回 0（并行提案改动的 mock 已由其工作流补齐）。
