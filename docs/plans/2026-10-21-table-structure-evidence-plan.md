# 表结构证据后端实施计划

依据：`docs/design/2026-10-21-table-structure-evidence.md` 中 TE-01 至 TE-04。

1. 为材料增加平台来源元数据 `origin`，补齐默认值、Alembic 迁移、材料读接口、Pydantic 和 JSON Schema。前端已有可选来源类型，保留现状。
2. 固定表结构 JSON 的格式与表排序，组装工作包时保存为普通材料；收据与上传文件共用哈希去重、源文件、分块和证据校验。
3. 收据在运行占用时写入材料清单，复用普通材料上传和行号索引，`tables_file` 指向同一份文件；修复轮次继续引用固定输入。
4. 覆盖重复组装、结构变化、上传内容一致、运行材料清单、证据校验、来源读接口、用量和删除保护、迁移升级与旧数据默认值。
5. 所有编辑完成后统一执行后端全量 pytest、Ruff；修复失败后记录结果。不修改 DataAgent 集成，不提交或推送。

命名规则：单连接使用“表结构收据 · 连接名 · UTC 日期”；多连接合并本轮全部表，使用“表结构收据 · 多连接（N） · UTC 日期”。名称不参与哈希，相同内容保留首份名称和来源。
