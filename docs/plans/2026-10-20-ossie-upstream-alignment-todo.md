# Ossie 上游结构跟进（待办）

状态：暂缓（2026-10-20 用户决定）。上游 `0.2.0.dev0` 仍是未发布的开发版，结构在变；核心模型与 Ossie 解耦，跟进只涉及适配器，等上游稳定或有团队实际文件需要互通时再启动。启动前先写设计文档并确认下方业务决定。

## 背景

- 当前对齐：上游提交 `88e0011`（2026-07-31），见 `apps/api/src/ontofoundry_api/adapters/ossie/PROVENANCE.md`。
- 2026-10-20 调研到的最新提交：`fcc4203`（2026-10-19）。
- 主要变化（均已合并）：本体、语义模型、映射可拆成三类独立文档并按 `name`/`iri` 互相引用；独立语义模型去掉包装层；内嵌 `semantic_model` 必须自带 `version`；旧内嵌写法弃用未移除；新增 `prefixes`/`iri`；映射树与键数组校验收紧；新增 `OSSIE_SQL_2026` 方言；schema 文件改名为 `ossie-schema.json`。
- 尚未合并、不跟进：数据集级指标（PR #343）、分析层级（Discussion #160）。

## 已知影响

| 范围 | 现状 |
|---|---|
| 导出 | 内嵌 `semantic_model` 缺 `version`，新版 schema 校验不通过；补上后结构校验可通过 |
| 导入新版内嵌文件 | 对象可导入，数据集、映射、指标被跳过并报错 |
| 导入三类独立文件 | 不支持 |
| YAML | 只解析 JSON |
| 测试 | 只用旧 schema 校验，通过不代表与新版互通 |

核心模型不需要改：文档拆分、包装、引用解析、`version` 都是适配器职责。

## 待办（启动时按序）

1. 固定新的上游提交与 schema，保留旧写法的兼容读取。
2. 导出内嵌模型补 `version`；导入同时接受旧内嵌与新内嵌写法，规范化写进转换报告。
3. 支持三类独立文件导入（引用解析、缺依赖报告）；支持 YAML 或与团队约定只交换 JSON。
4. `OSSIE_SQL_2026` 的可支持子集，不支持的表达式明确报告。
5. 增加新版样例与往返测试：旧→核心、新→核心、核心→内嵌、核心→三文档。
6. 增加三文档导出，保留内嵌导出，按目标工具能力选择。
7. 同步设计 §5–§7、§7.1/7.2 与 PROVENANCE，更新[与 Ossie 的关系](../concepts/ossie-compatibility.md)中的对齐版本。

## 启动前需要确认

| 决定 | 例子（虚构） | 推荐 |
|---|---|---|
| 只有语义模型、没有本体的文件是否接收 | 文件只有“借阅流水”数据集和“借阅次数”指标 | 允许作为“仅数据集与指标”导入，不自动造对象 |
| 同一对象映射到多个独立模型 | “借阅”同时映射“当前借阅”和“历史借阅” | 默认标为冲突待补全，由用户确认合并方式 |
| 是否保留跨系统 IRI 身份 | 两团队把同一 IRI 分别命名为“借阅人”“会员” | 有明确互通需求再单独设计，不顺手加字段 |
| 跨文件同名数据集是否合并 | 两份模型都有“图书目录”，一份快照一份当前状态 | 默认分开；同一模型文件被重复引用才去重 |

另需了解：其他团队使用的 Ossie 工具与版本（只读内嵌，还是支持三文档）、交换 JSON 还是 YAML，并尽量取得真实样例做往返比对（样例不入库）。
