# 本体读取性能优化实施计划

日期：2026-10-23。依据：[设计方案](../design/2026-10-23-ontology-read-performance.md)。P0 已完成；用户于 2026-10-23 授权依次实施 P1、P2、P3，每阶段统一测试、真实测量，通过后在 main 提交，不 push。无 core-1 概念变化，不迁移存储。

## 1. P0：稳定回调与隐藏请求生命周期（本次）

1. 阅读 AGENTS.md、审查和现行接口/视觉规范，先形成设计及计划。
2. useElementDetail 的 href/open 改用正确依赖的 useCallback；OntologyViewPage 直接传 open，移除渲染期间 ref 转存。
3. ElementInspector 将页面激活且页签可见的信号传入请求面板；实例列表和关联实例的启动、成功、失败及结束处理都受生命周期约束；固定版本/会话 revision 更换时隔离局部状态。保留已访问 DOM 和统一草稿。
4. 同步处理其他请求面板的可见性及迟到回写，覆盖指标预览、数据集校验/预览和其元数据读取；不改变接口、布局、设计变量或 core。
5. 补跨页签修改/统一保存、取消后恢复和重新读取、409 后各页签修改保留、关闭重开/换元素/版本、隐藏请求和迟到成功/失败测试。验证 URL 会话和工作空间变化时稳定回调仍使用新依赖。
6. 全部编辑完成后统一执行 apps/web 的 `npm run test -- --run`、`npm run build`、`npm run test:visual`，记录完整失败原文和必要重跑。1440×900 对比受影响页面，检查图谱状态、返回表格与展开；通过局域网 IP 的 HTTP 验证一次。只在预期视觉变化且有依据时更新基准，并说明原因。
7. 汇总改动文件、测试结果、未覆盖限制和 D4/D6–D9 待确认项。本次不把未实测候选性能目标标成完成。

## 2. P1：共享固定版本定义

前置：确认 D4、D6、D7；对虚构基准数据记录冷/暖网络和浏览器耗时。

- 在 client.ts 统一读取固定 version_id 的 presentation；新增带主体/授权代次、工作空间、版本与表示键的共享读取层，合并 Promise，失败驱逐、独立草稿、LRU 和账号/权限清理。
- 迁移 useSnapshot、OntologyViewPage、ElementInspector 及其他读取者；实例单独读取，校验其版本上下文；保留旧 published-snapshot 兼容路径和会话/待发布预览语义。
- 任何响应体边界变化同批更新 read_models.py、api-read schema、前端 types/client 和契约测试；纯复用接口则不制造新字段。
- 全部编辑后统一验证：两个消费者只下载一次、消费者关闭隔离、失败重试、登出/撤权、不修改共享对象、指针和定义之间发布新版本仍一致、409 和取消。
- 验收：目录→详情→弹窗固定版本一次完整定义下载/解析；传输候选减少 50%/67%，真实打开时间单测，达到设计候选目标后再进入下一阶段。
- 回退：切回旧读取入口，保留固定版本一致性，关闭共享功能不影响发布数据。

## 3. P2：服务端缓存和 ETag

前置：确认预算 D7、指标 D9，P1 正确性通过；分别采集数据库、校验、哈希、派生和序列化成本。

- 扩展 services/read_cache.py：按估算字节和条目驱逐、同键计算合并、失败清理、指标、多 worker 预算；不保存 ORM/Session，不引入分布式缓存。
- 扩展 domain/graph.py DraftIndex：归属、父子、双向邻接及纯版本派生；ontology_query/workspaces 复用。动态连接与登记元数据在返回边界读取。
- api/modeling.py、api/ontology.py 先鉴权，再按轻量元数据匹配弱 ETag；private/no-cache、正确 200/304 和条件列表/通配符处理。浏览器优先处理 HTTP 缓存；若手动处理，则 client.request 同步实现响应体复用和裸 304 恢复。
- 契约：纯 HTTP 头不改 core/schema；拆分响应时同批更新 read_models.py、api-read schema、types/client、REST 实际响应测试。
- 全部编辑后统一测试：同键并发一次计算、异常恢复、LRU 超预算、继承一致性、权限变化与版本归属、动态元数据失效、200/304、SQL/CPU/RSS。使用真实 API/PostgreSQL/Doris 测 1/10/30 并发和多 worker。
- 回退：关闭缓存或条件读取，直接由权威快照构造；结果一致，只有性能变化。

## 4. P3：目录摘要与按需详情

前置：确认 D8 接口兼容策略及 D9 阈值，P2 索引可用。

- 新增固定版本目录摘要分页端点和读取模型，不复用完整 resource_items 列表；游标绑定版本、权限、排序与筛选。
- get_type 按 ID/名称索引定位，按目标构造祖先与引用闭包；维持名称歧义和旧响应；属性/规则仍打开所属资源，不返回全空间实例。
- MCP 提前工具分派，共用索引与投影，保留响应大小/分段预算与工具兼容性。
- TypeCatalogPage、ElementInspector、OntologyViewPage 逐步使用摘要与详情；查看投影和完整 Draft 类型分开，进入编辑取固定版本完整基线，继续预检/影响确认/CAS。
- 同批更新 read_models.py、api-read schema、前端 types/client、REST/MCP 契约测试。新字段逐个解释来源、执行属性、删除影响及能否从定义推导。
- 全部编辑后统一验证：单 ID 不全量投影、目录不含完整定义、分页固定版本/权限、继承/自关联/虚拟父/共享绑定、历史版本、编辑隔离、MCP 兼容；使用四档虚构数据测冷暖性能与堆/RSS。
- 回退：保留旧列表端点和完整读取路径，逐调用者撤回，不更改权威快照。
