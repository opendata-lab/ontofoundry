## 一、现场导入（4 分钟）——架构治理

**初次导入：确认即为初始版本**

1. 首页 →「架构治理」→「本体视图」→ 切到「**语义视图**」→ 工具栏「**导入**」（「全局」页没有导入按钮）。
   对话框提示「空间还没有版本：确认导入报告后直接发布为初始版本」（初次导入不需要选导入方式）。
2. 本体文件选 `architecture-governance.ossie.json` →「**导入**」。
3. 导入报告：顶部是新增 **29 个对象、31 条关系、65 个属性、21 个映射**和操作按钮；**没有「未导入的内容」**
   （跳过 0 项）；「导入说明」折叠在最后（「已原生保留概念、角色、字段出现状态与数组顺序」）。
   旁白：「多角色关系、同义词、逻辑语义模型和指标都原样进来了，不需要为平台改模型。」
4. 「**确认并发布为初始版本**」→ 提示「已发布为 v1」→「完成」。
5. 「语义视图」：架构治理的概念网络；「全局」的数据映射层显示导入的映射。

**再次导入：先对比，再合并**

6. 再点「导入」（仍在「语义视图」工具栏）：对话框提示「空间已有 v1：导入后进入对比与合并」，导入方式默认「合并」。
   选同一个文件 →「导入」→ 报告里新增和更新都是 **0**（内容没变就不算更新）。
7. 「**对比并合并**」→ 进入发布页：与 v1 三方合并，变更为 0。
   旁白：「换成修改过的文件，这里会逐项列出差异；和线上有冲突的字段逐项选择保留哪边，确认后才发布新版本。」
   （演示不发布这次合并，直接回到本体视图。）

## 二、导入后增量建模（4 分钟）——中金所账户模型

1. 首页 →「中金所账户模型」→「本体发布」→「版本历史」：v1「导入手工模型 account_model_v2」。
   「本体视图」→「语义视图」：交易所、会员、专用资金账户等 21 个对象。
   提前说明：「源文件用英文技术名命名概念（如 dedicated_fund_account），中文名在说明里；平台原样保留。」
2. 「本体构建」→「+」新建会话 → 上传《保证金账户冻结管理办法》→ 粘贴目标范围 →「**开始建模**」。
   旁白：「智能体先通过 MCP 读刚导入的模型，复用已有概念，只提新增的部分。」通常约 4 分钟。
   - **超过 6 分钟仍无结果，或出现失败/网络错误，立即改选「账户冻结（备用）」**，不要现场重试。
3. 提案里指出：新对象 `account_freeze_record`（说明里是「账户冻结记录」，命名沿用源模型的英文风格），它与**已有的**专用资金账户、交易所、结算会员的关系（复用，不重复建），
   3 条规则，以及冻结登记里的 2 条记录（实例；只有原文给出的值，解冻日期为空的就是空）。
4. 「接受全部无冲突项」→「发布本体」→「**发布 v2**」→ 发布说明 `新增账户冻结` →「确认发布」。
5. 「版本历史」→ 对比 v1、v2：增量清清楚楚。

## 三、导出（1 分钟）

1. 「本体发布」→「版本历史」→ v2 行点「**Ossie JSON**」下载。
2. 旁白：「导出的是标准 Apache Ossie，包含刚才的增量；原有内容逐字段保留，平台信息只在 Ossie 规定的扩展位，
   任何遵循标准的工具都能读，再导入结果一致。」

## 可能被问到

| 问题 | 回答 |
| --- | --- |
| 真的无损吗？ | Ossie 能表达的全部原样承载；导出去掉平台扩展后与原文件逐字段一致，自动化测试用这两份真实文件守护 |
| 平台加了什么？ | 只有 Ossie 表达不了的：中文显示名、稳定 ID、证据，放在 Ossie 规定的扩展位，其他工具忽略即可 |
| 指标能直接查吗？ | MCP 提供 `list_metrics`（按名称/同义词找，如「核心服务数」）和 `query_metric`：单数据集指标生成只读 SQL 并执行，快照数据必须指定日期或 `as_of`，避免跨快照重复累加；本环境未接架构治理的真实库，只返回 SQL |
| 增量会不会把导入的模型改乱？ | 只出提案，人接受才进入草稿；发布时与当前版本三方合并，冲突逐项处理；版本可对比 |
| 导入会覆盖已有模型吗？ | 导入只生成草稿，发布是单独一步，发布前可看差异 |
