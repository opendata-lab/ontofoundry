# 值类型

[概念概览](README.md) · [值类型设计](../design/2026-10-20-value-types.md)

## 1. 概述

值类型是本体里的“属性类型库”：给一类值起名字并统一口径，多个属性共用。例如“金额：小数，不小于 0，最多两位小数”“会员等级：文本，只能是普通、银卡、金卡”。值类型不是业务实体，没有实例、关系或标识。

属性的类型二选一：七种内置类型之一，或引用一个值类型。引用值类型的属性继承它的基础类型和约束；属性自己的约束只能在此基础上收窄。

## 2. 字段

| 字段 | 类型 | 填写要求 | 说明 |
|---|---|---|---|
| `id` | UUID | 必须提供。 | 稳定身份，属性按 id 引用。 |
| `name` | 字符串 | 必须提供，ASCII 英文标识。 | 与实体类型共用英文标识（忽略大小写不能重复），不能使用内置类型名（String、Decimal 等）。 |
| `display_name` | 字符串 或 null | 可以为空。 | 中文名称。 |
| `value_kind` | 七种内置类型之一 | 必须提供。 | 基础类型。不支持值类型继承值类型。 |
| `description` | 字符串 | 可以省略。 | 业务含义。 |
| `Property.value_type_id` | UUID 或 null | 引用值类型时填写。 | 引用后属性的 `value_kind` 必须等于值类型的基础类型。 |

约束是归属于值类型的规则（`owner_kind = value_type`，只能是约束），表达式用值类型的英文标识表示当前值：

| 值类型 | 基础类型 | 约束 |
|---|---|---|
| money（金额） | 小数 | `money >= 0`；`money = ROUND(money, 2)` |
| member_level（会员等级） | 文本 | `member_level IN ('普通', '银卡', '金卡')` |
| mobile_phone（手机号） | 文本 | `REGEXP_LIKE(mobile_phone, '^[0-9]{11}$')` |

## 3. 规则

- 约束只说明“有值时什么值合法”，不判断空值；是否必填仍在属性上设置。
- 生效条件 = 值类型的全部约束 AND 属性自己的约束。平台不判断约束是否互相矛盾；例如等级只允许普通、银卡、金卡，属性规则却只允许铂金，仍可保存，实例校验会显示每一行都违反约束。
- `REGEXP_LIKE` 只接受字符串常量模式，不支持反向引用、环视或内联模式。
- 使用中的值类型不能直接删除，需先改绑或删除引用它的属性；修改基础类型时，使用它的属性在同一批里一起修改。
- 使用数和“哪些属性使用”实时推导，不保存在模型里。

## 4. 界面

本体对象目录的“值类型”页签列出名称、英文标识、基础类型、约束、使用属性数和描述，不设详情页；新建和编辑用弹窗，“使用属性”可展开并跳到属性所在的实体类型。查看属性或实体类型的规则时，继承自值类型的约束置灰、不可编辑，并标明“继承自值类型 X”，点击 X 跳到目录的值类型页签。

## 5. Ossie

Ossie 的 `ValueType` 导入为值类型，`requires` 导入为值类型的约束；值类型之间的继承折叠为基础类型，祖先的约束复制到本值类型（RT-24）。导出时还原为 Ossie `ValueType`，约束写入 `requires`，中文名称写入扩展文件；不引用值类型的属性（包括标识属性）直接引用内置类型，不生成辅助值类型。
