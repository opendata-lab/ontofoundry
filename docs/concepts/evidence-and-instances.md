# 证据与实例

[概念概览](README.md) · [实例库设计](../design/2026-10-21-instance-store.md)

## 存储边界

本体元数据仓库保存对象类型、属性、关系定义、规则、指标、数据集和映射。core-1 草稿、版本快照与原生包只含定义，不再含 `material_objects`、`material_links`。旧快照中的实例在切换时丢弃，不迁移。

文档实例保存材料中描述的实体和属性值，关系实例保存实体之间的联系；两者独立存于工作空间实例库，通过 UUID 引用本体定义。现有提案英文种类 `material_object`、`material_link` 保持；它们不再是核心模型集合。数据库实例通过映射只读查询业务源，不复制、不建平台实体索引。

## 生效与并发

接受实例提案时，能按当前发布版本完整校验，且使用的定义与会话定义解释一致，则立即 active；依赖新类型、新属性、改动过的属性或关系（包括关系两端）时为 staged，只有所属会话可管理。发布时按合并模型统一校验，再转 active。实例不产生本体版本。

每条实例带 revision。更新与撤销必须比较 revision，防止跨会话覆盖和内容改回后的误覆盖。实例内容、关系、证据、修改历史与提案决定在同一事务内写入。删除为软删除，关联关系同时失效，历史保留修改人、时间、提案和改前改后内容。

取消任务、切换会话和关闭页面保留 staged 实例。只有显式放弃会话会删除该会话 staged 实例；前端二次确认，接口幂等，并记录操作者、时间和逐条删除历史。active 实例保留。

## 定义发布与读取

删除被实例引用的类型、属性、关系，修改属性英文标识或值类型，修改关系端点，都会阻止发布；需先处理实例。改描述、显示名、同义词不阻止。检查覆盖会话发布和元素详情保存。其他会话 staged 实例不阻止当前发布，在其所属会话发布时重新校验。

实例是实时数据。MCP `search_objects`、`get_object` 和 REST 文档实例读取只返回 active；固定历史版本按该版本校验，过滤不兼容的实例并报告过滤数量。不创建实例快照，不用旧定义解释新值。分页游标与发布预览都绑定实例集合变更序号，实例变化后须重新读取或预览。数据库实例仍通过源系统按需查询。

显示文本依次由标题属性、完整业务标识元组、可见材料引文、实例 UUID 推导，不持久化。0 与 false 是有效显示值；不同 UUID 即使业务标识相同也分别返回。重复提示只辅助审阅，不自动合并；`fact_revision` 仍只修订待审新增提案为已有实例更新提案，真正写入发生在接受事务中。

## 证据

实例证据单独存表，可按材料查询。材料证据沿用 `id`、`material_id`、`material_sha256`、`locator`（heading、line_start、line_end）及 quote；须验证同空间材料、内容哈希、行号和真实引文。人工证据沿用 id、note、created_by、created_at；作者和时间由服务端填写，保存后不能修改，只有作者可以从仍存在的实例移除。智能体不能增删改人工证据。

例如虚构退货登记写着“R-1 退款 50 元”，实例值保存单号 R-1 与退款 50，证据指向原文行号。R-2 金额待确认时保持缺值并提示补全，不能编造零值。证据说明出处，不表示实例已经核实为真。

定义证据仍随定义保存；实例证据、实例历史、提案、导入、运行清单及版本引用共同决定材料能否删除。已删除实例和历史证据也阻止删除材料。无实例读取权限不能读取实例和证据。

本期原生单文件、完整包和 Ossie 导出都不含实例。原生完整包只携带定义及其材料证据；实例导出另议。
