# 对象类型

[概念概览](README.md) · [主设计文档 §3.2、§8A](../design/2026-10-14-core-model-and-format-adapters.md)

本文说明 core-1 的目标模型与行为，状态为设计定稿、待实施。JSON 示例中的业务和数据来源均为虚构；片段不是完整导入包，完整包形式见[格式与转换](formats.md)。字段表逐项说明何时填写、空值与默认行为。

## 2026-10-20 命名与交换约定

对象、属性、关系、规则和指标统一使用必填 `name`（英文标识，`^[A-Za-z_][A-Za-z0-9_]*$`）和可选 `display_name`（中文名称）。名称为空时界面显示 name，名称可重复；英文标识沿用原命名空间与引用规则。Dataset 不变。关系的完整含义及角色名不变。旧数据库内容清理，不转换；旧外部文件由导入适配器转换并报告。

Ossie 导出为 ZIP：纯 Ossie 文件与 `ontofoundry-extension.json`。显示名仅在扩展 `display_names`；同义词在支持的位置用 `ai_context.synonyms`，概念和本体关系使用扩展 synonyms。单个 Ossie 文件导入显示名为空；旧版扩展块仅导入兼容。详见[命名统一设计](../design/2026-10-20-display-name-unification.md)。

## 1. 概述

一张订单会有订单号、金额和状态，还可能属于某个客户。“订单”是对象类型，“O-1001”是一个订单实例。对象类型让这些实例使用同一份定义，便于关联、解释和查询。

当一种业务事物需要被独立识别和讨论时，建立对象类型，例如客户、员工或订单。客户的名称只是客户的一个值，应建为属性；每日销售汇总表只是一个来源，也不必为了统计而建对象。对象定义保存业务名称、范围、同义词、继承和实例标题；属性、关系和绑定各自保存，用 id 引用对象。指标只引用登记数据集列，与对象不建立关联。

## 2. 字段

| 字段 | 类型 | 填写要求 | 说明 |
|---|---|---|---|
| `id` | UUID | 必须提供。 | 此字段保存定义的稳定身份，改名不会改变它。 |
| `display_name` | 字符串 / null | 可选。 | 中文名称；空时显示 name，允许重复。 |
| `name` | 字符串 | 必须提供。 | 此字段给出工作空间内的对象英文标识，例如 sales_order。 |
| `description` | 字符串 | 可以省略。 | 此字段解释业务含义、范围和必要上下文。 |
| `synonyms` | 字符串数组 | 可省略，默认空数组。 | 这些业务别名用于搜索和问答理解。 |
| `tags` | 字符串数组 | 可省略，默认空数组。 | 这些标签用于管理和整理对象定义。 |
| `extends` | UUID 或 null | 可以为空或省略。 | 此字段引用唯一父对象，继承定义保持原 id，不复制到子对象。 |
| `title_property_id` | UUID 或 null | 可以为空或省略。 | 此字段选择实例标题属性，可以引用祖先定义的属性。 |
| `derived_by` | DerivedBranch 数组 | 可省略，默认空数组，非空时仅子对象可填。 | 成员派生定义，分支取并集，simple 条件与 expression 互斥，见[继承](inheritance.md)。 |
| `evidence` | Evidence 数组 | 可省略，默认空数组。 | 这些证据说明该定义的业务依据。 |

标题属性参考 Palantir Foundry，由建模 Agent 在材料或表结构明确给出实体名称属性时设置；保持可选，没有名称属性时不设、按标识显示，平台和脚本不从字段名推断。

## 3. 例子

以下对象及其标题属性来自通用订单场景。其他订单属性与绑定见[基础销售完整样例](../design/core-1-examples/01-basic-sales.json)。

```json
{
  "object_types": [
    {
      "id": "00000000-0000-4000-8000-000000001002",
      "display_name": "订单",
      "name": "sales_order",
      "description": "客户的一次下单\n\n采用指标时保留其固定过滤；完成率的已完成条件仅作用于分子。",
      "synonyms": [
        "销售单"
      ],
      "tags": [
        "核心"
      ],
      "extends": null,
      "evidence": [],
      "title_property_id": "00000000-0000-4000-8000-000000002011",
      "derived_by": []
    }
  ],
  "properties": [
    {
      "id": "00000000-0000-4000-8000-000000002011",
      "owner_type_id": "00000000-0000-4000-8000-000000001002",
      "display_name": "订单号",
      "name": "order_no",
      "description": "",
      "value_kind": "string",
      "required": true,
      "identifier": true,
      "unique": true,
      "synonyms": [],
      "evidence": []
    }
  ]
}
```

对象弹窗展示订单定义、属性和关系；指标在语义视图查看。是否在对象详情按绑定推导展示相关指标，由工程和原型阶段决定，模型不保存关联。实例的标题取订单号；若该属性未指定或实例无值，按下述规则回退。标题是展示值，不改变实例身份。

文档事实读取时依次用有效标题属性值、完整业务标识元组、可见非空材料 quote 的前 80 个字符、事实 UUID 推导 display_text。null 和空字符串无显示值，0 和 false 有值；标识按属性 UUID 顺序，缺任一项就跳过整组；多个 quote 按证据 UUID 顺序取首项，截断只影响显示。只有人工 note 或无可见引文时继续回退 UUID。UI 与 MCP 的 display_text 只读，不写入核心；搜索覆盖推导显示文本和属性值。数据库实例仍按标题、完整标识、物理键回退。

## 4. 建模建议

| 订单号 | 客户编号 | 金额 |
|---|---|---|
| O-1 | C-1 | 100 |
| O-2 | C-1 | 50 |

正例：定义订单与客户两个对象，得到两张订单、一个客户，订单金额是属性。

反例：把“金额”也建对象，会把 100、50 当成可独立识别的业务实例；这里它们只是订单的值。

当业务有独立身份与生命周期时建立对象。例如“客户”需要与订单关联，是对象；“客户名称”是客户的值，应为属性。一个数据库有多张表，并不意味着每张表都要成为对象，同一对象可以横向绑定多个来源。

正例：“供货记录”同时连接供应商、组件和仓库，数量属于这次供货。反例：把三方参与的供货直接塞入带三个端点的关系，core-1 只接受二元关系。

对象描述应说明业务范围，例如“已提交的销售订单，不包括购物车”；不要把物理连接凭据写入描述。真实说明直接展示，不藏在信息图标里，也不建立“高级”入口。

## 5. 校验与限制

对象英文标识工作空间内唯一，忽略大小写；语法为 `^[A-Za-z_][A-Za-z0-9_]*$`；SQL 保留字也可用作英文标识，物理引用由 agent 按方言处理。继承单父无环，不能遮蔽继承属性或关系。标题属性必须是本对象或祖先的有效属性。

无绑定叶对象是待补全对象，不能假装可查数据库。无绑定且有具体后代的虚拟父对象按[继承](inheritance.md)展开来源，不直接接收文档事实。对象可以暂时没有标识，文档事实仍可保存，但须提示补全。

导出 Ossie 时，英文标识不能与其内置概念名冲突；例如名为 String 的业务对象必须先改名，否则导出报错。

## 6. 与 Palantir Foundry、Microsoft Fabric IQ、Apache Ossie 的对照

核查日期：2026-10-15。以下依据官方公开文档；Fabric IQ 的本体功能处于预览阶段。概念对应不表示字段、执行能力或往返行为相同，未实测外部租户。

Palantir 的 [Object type](https://www.palantir.com/docs/foundry/object-link-types/type-reference)同样区分类型与对象实例；其具体字段与存储能力不等于 core-1。

Fabric 的 [Entity type](https://learn.microsoft.com/en-us/fabric/iq/ontology/how-to-create-entity-types)支持先定义属性再绑定数据。[元数据文档](https://learn.microsoft.com/en-us/fabric/iq/ontology/how-to-add-metadata)说明实体描述与同义词可为 agent 提供业务上下文。

Ossie 的 [EntityType](https://github.com/apache/ossie/blob/main/ontology/ontology.md#concepts)对应业务实体概念。它以嵌套 relationships 组织属性及关系；core-1 以扁平集合和 id 组织。显示名、同义词、标签与标题属性使用本平台扩展文件，不宣称是其标准同名字段。
